# Apache Maka

- URL: https://github.com/apache/maka
- Date: 2026-08-23
- Repo snapshot studied: `main` @ `cded1950b75354972d4d097966aae4bca7df17d3`
- Why picked today: GitHub's trending page surfaced `apache/maka`, and the GitHub repo API showed 2,244 stars with activity pushed on 2026-08-23 when checked. More importantly, this is not another thin "agent shell." The repo has a clear systems thesis: one Runtime Host, one canonical event log, and several product surfaces that are projections over the same execution spine.

## Executive summary
`Apache Maka` is worth studying because it treats local agent work as runtime architecture, not as a UI feature. The core move is stated plainly in [`ARCHITECTURE.md`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/ARCHITECTURE.md): Desktop, TUI, CLI, bots, and eval clients all go through one Runtime Host. That means session identity, tool execution, permissions, continuation, and event emission are not duplicated across surfaces.

The second smart move is the log-first model. The root [`README.md`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/README.md) says model messages, tool calls, tool results, and termination facts are written down as recoverable execution facts. The architecture doc sharpens that further: the Runtime Event Log is canonical, while context pruning and UI projections are derived views. That is a much better mental model than "chat transcript plus some subprocess output."

The repo structure backs up the claim. [`package.json`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/package.json) splits the system into dedicated workspaces for [`apps/desktop`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/apps/desktop), [`packages/core`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/core), [`packages/runtime`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime), [`packages/runtime-host`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime-host), [`packages/storage`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/storage), [`packages/eval`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/eval), [`packages/cli`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/cli), and [`packages/ui`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/ui). That is the shape of a real product runtime, not a demo.

The weak side is that this seriousness comes with real sprawl. The workspace count is high, the runtime export surface is huge, and the project is still in incubation. The same README that sells local-first durability also documents a plaintext local [`credential-vault.json`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/README.md#local-data-and-recovery) and limited platform support. The architecture is strong; the operational maturity is still catching up.

## What they built
They built a local-first agent workspace with several distinct but intentionally unified surfaces:

- An Electron desktop app in [`apps/desktop`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/apps/desktop), with separate [`src/main`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/apps/desktop/src/main), [`src/preload`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/apps/desktop/src/preload), and [`src/renderer`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/apps/desktop/src/renderer) layers.
- A shared contract layer in [`packages/core`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/core), whose package manifest and source tree expose session, runtime-event, permission, orchestration, model, graph, task-ledger, scheduled-task, and tool-catalog types.
- The actual runtime in [`packages/runtime`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime), where agent execution, context management, tools, compaction, goals, computer use, web search, and model adapters live.
- A public execution boundary in [`packages/runtime-host`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime-host), with separate [`protocol`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime-host/src/protocol), [`server`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime-host/src/server), and [`transport`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime-host/src/transport) subtrees.
- A storage layer in [`packages/storage`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/storage) and an evaluation layer in [`packages/eval`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/eval) so benchmarking does not become a second hidden runtime.

## Why it matters
Most agent products accumulate execution logic accidentally. Desktop owns one loop, CLI owns another, eval has a special path, and soon nobody knows which surface is truth. Maka is worth studying because it rejects that drift.

1. The architecture document makes Runtime Host the only execution authority instead of letting surfaces grow their own runtimes.
2. The repo separates pure contracts from runtime behavior. [`packages/core/src/runtime-event.ts`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/core/src/runtime-event.ts), [`packages/core/src/runtime-boundary.ts`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/core/src/runtime-boundary.ts), and [`packages/core/src/session.ts`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/core/src/session.ts) keep the protocol surface explicit.
3. The runtime package is not just "call model, then call tool." Its manifest exposes dedicated modules for [`agent-run.ts`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime/src/agent-run.ts), [`ai-sdk-backend.ts`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime/src/ai-sdk-backend.ts), [`builtin-tools.ts`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime/src/builtin-tools.ts), [`goal-tools.ts`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime/src/goal-tools.ts), and [`computer-use-tools.ts`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime/src/computer-use-tools.ts).
4. Eval crosses the same public boundary as everything else. That is rare, and it matters, because it forces benchmark behavior to exercise the real product seams.

## Layered architecture dissection
### High-level system shape
The system shape is simple in principle and disciplined in execution: product surfaces submit work to Runtime Host, Runtime Host manages session identity and admission, SessionManager and AgentRun drive execution, tools and models emit canonical runtime events, and every UI or recovery feature reads projections from that event history.

### Main layers
**1. Surface layer**  
[`apps/desktop`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/apps/desktop) is the visible product shell, while [`packages/cli`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/cli) covers TUI and non-interactive runs. The Desktop subtree itself is sensibly split into [`src/main`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/apps/desktop/src/main), [`src/preload`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/apps/desktop/src/preload), and [`src/renderer`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/apps/desktop/src/renderer).

**2. Contract layer**  
[`packages/core/package.json`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/core/package.json) and the [`packages/core/src`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/core/src) tree show the repo's type backbone. Files like [`runtime-event.ts`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/core/src/runtime-event.ts), [`canonical-runtime-event.ts`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/core/src/canonical-runtime-event.ts), [`session.ts`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/core/src/session.ts), and [`tool-catalog.ts`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/core/src/tool-catalog.ts) define the stable vocabulary the rest of the product consumes.

**3. Runtime layer**  
[`packages/runtime/package.json`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime/package.json) is revealing all by itself. The export map names the real concerns: session manager, runtime kernel, runtime read model, tool runtime, shell tools, built-in tools, goal tools, computer-use tools, web tools, memory extraction, graph coordination, and history compaction. The corresponding source tree under [`packages/runtime/src`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime/src) has concrete files for those concerns.

**4. Runtime Host boundary**  
[`packages/runtime-host/src`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime-host/src) is the public execution seam. The split across [`protocol`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime-host/src/protocol), [`server`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime-host/src/server), [`transport`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime-host/src/transport), and files like [`candidate-entry.ts`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime-host/src/candidate-entry.ts) and [`execution-candidate-main.ts`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime-host/src/execution-candidate-main.ts) suggests the team is serious about process, protocol, and isolation boundaries.

**5. Persistence and projection layer**  
[`packages/storage`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/storage) plus the README's local workspace description tie the architecture to durable local state. The product stores operational state under `runtime.sqlite` and related workspace files, then projects conversation, artifacts, and recovery views out of that state.

**6. Eval and graph layer**  
[`packages/eval`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/eval) is deliberately not a secret fork of the runtime. [`ARCHITECTURE.md`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/ARCHITECTURE.md) and the linked [`docs/architecture/agent-graph-stream-scheduling-draft.md`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/docs/architecture/agent-graph-stream-scheduling-draft.md) show the design intention: graph scheduling and evaluation both route back through the same runtime authority.

### Request / data / control flow
1. A user interacts through Desktop, TUI, CLI, or a bot, as described in [`README.md`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/README.md) and [`ARCHITECTURE.md`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/ARCHITECTURE.md).
2. The request crosses Runtime Host, whose public-facing implementation lives under [`packages/runtime-host/src`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime-host/src).
3. Runtime Host hands lifecycle work to SessionManager and AgentRun, reflected in the runtime package exports and files like [`agent-run.ts`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime/src/agent-run.ts).
4. Model calls, tools, goals, and optional computer use run through dedicated runtime modules such as [`ai-sdk-backend.ts`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime/src/ai-sdk-backend.ts), [`builtin-tools.ts`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime/src/builtin-tools.ts), [`goal-tools.ts`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime/src/goal-tools.ts), and [`computer-use-tools.ts`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime/src/computer-use-tools.ts).
5. Execution facts become canonical runtime events as defined in [`packages/core/src/runtime-event.ts`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/core/src/runtime-event.ts) and explained in [`ARCHITECTURE.md`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/ARCHITECTURE.md).
6. Storage and UI then project those facts into conversation state, artifact views, recovery, and evaluation results rather than inventing parallel truths.

## Important components
The most important component is Runtime Host as described in [`ARCHITECTURE.md`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/ARCHITECTURE.md) and implemented under [`packages/runtime-host/src`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime-host/src). That is the boundary that stops the product from fragmenting into per-surface runtimes.

The second is the contract surface in [`packages/core/src/runtime-event.ts`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/core/src/runtime-event.ts), [`packages/core/src/runtime-boundary.ts`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/core/src/runtime-boundary.ts), and [`packages/core/src/session.ts`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/core/src/session.ts). These files are the difference between an architecture and a pile of callbacks.

The third is the runtime execution cluster in [`packages/runtime/src/agent-run.ts`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime/src/agent-run.ts), [`packages/runtime/src/ai-sdk-backend.ts`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime/src/ai-sdk-backend.ts), and [`packages/runtime/src/builtin-tools.ts`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime/src/builtin-tools.ts). That is where the repo stops talking about local-first systems and starts implementing them.

The fourth is the graph and continuation surface, hinted at by [`packages/runtime/src/agent-graph-timeline.ts`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime/src/agent-graph-timeline.ts), [`packages/runtime/src/goal-tools.ts`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime/src/goal-tools.ts), and [`docs/architecture/agent-graph-stream-scheduling-draft.md`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/docs/architecture/agent-graph-stream-scheduling-draft.md). ## Practical questions and answers
**Is this basically an Electron shell around a model API?**  
No. [`README.md`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/README.md), [`ARCHITECTURE.md`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/ARCHITECTURE.md), and the workspace split in [`package.json`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/package.json) show a runtime product with multiple clients, not a renderer-first app.

**Where is the canonical history?**  
In the Runtime Event Log described in [`ARCHITECTURE.md`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/ARCHITECTURE.md). Prompt compaction changes provider input, not stored history.

**Does eval use a private shortcut runtime?**  
Apparently not. The architecture doc explicitly says a Maka subject crosses the public Runtime Host client/protocol boundary, while eval owns experiment semantics only.

**What should I read first if I want to understand the system fast?**  
Start with [`README.md`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/README.md), then [`ARCHITECTURE.md`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/ARCHITECTURE.md), then [`package.json`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/package.json), [`packages/core/package.json`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/core/package.json), and [`packages/runtime/package.json`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime/package.json).

**Where is the real product complexity?**  
In the combination of [`packages/runtime`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime), [`packages/runtime-host`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime-host), and the event/contract layer in [`packages/core`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/core), not in the window chrome.

## What is smart
- Making Runtime Host the single execution authority instead of letting every surface grow a private runtime.
- Treating runtime events as canonical facts, with context and UI as projections.
- Separating pure contracts in [`packages/core`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/core) from operational logic in [`packages/runtime`](https://github.com/apache/maka/tree/cded1950b75354972d4d097966aae4bca7df17d3/packages/runtime).
- Forcing eval through the same public boundary as real product execution.
- Naming advanced capabilities like goals, graph scheduling, memory, search, and computer use as explicit runtime modules rather than magical prompt branches.

## What is flawed or weak
- [`package.json`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/package.json) reveals a large workspace surface, which means real contributor and maintenance overhead.
- [`README.md`](https://github.com/apache/maka/blob/cded1950b75354972d4d097966aae4bca7df17d3/README.md) makes clear the project is still in incubation and active change, so builders should expect churn in data formats and commands.
- The same README documents a local plaintext `credential-vault.json`, which is practical but not an especially strong secret-management story.
- Platform support is still uneven: macOS arm64 first, Windows preview, Linux not yet supported. That is fine for an emerging desktop tool, but it limits the current production posture.

## What we can learn / steal
- Put every product surface behind one runtime boundary if you want consistency.
- Keep execution history canonical even when you compact context for cost.
- Split contracts, runtime behavior, host boundary, storage, and eval into separate packages early if the product is going to grow.
- Make benchmark/eval traffic exercise the same runtime seam as normal usage, so evaluation does not lie.

## How we could apply it
If we were building our own local agent product, I would copy the Runtime Host plus event-log projection model almost verbatim. I would likely start with fewer workspaces and a stronger secret-storage story, but the core discipline here is right: UIs should be clients of a runtime, not the owners of execution truth.

## Bottom line
`Apache Maka` feels like a serious attempt to build a local agent operating environment rather than a desktop wrapper around chat.

The strongest builder lesson is simple: pick one runtime authority, keep an append-only execution record, and let everything else become a projection. Maka shows that idea clearly in code and docs, even if the project is still early and operationally rough around the edges.
