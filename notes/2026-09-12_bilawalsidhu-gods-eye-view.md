## Executive summary
[`bilawalsidhu/gods-eye-view`](https://github.com/bilawalsidhu/gods-eye-view/tree/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac) is a browser-based spatial intelligence console: a Cesium globe, optional Google/Cesium photorealistic 3D tiles, live aircraft, ships, satellites, earthquakes, traffic, CCTV, bike-share, radio, fires, military installations, and voice-driven control. The README sells the cinematic "spy satellite simulator" feel, but the more interesting source story is the amount of engineering required to keep dozens of public, flaky, quota-limited feeds usable in a local browser app.

The repo is organized around a browser application shell, a data-layer manager, many layer modules under [`src/data`](https://github.com/bilawalsidhu/gods-eye-view/tree/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/data), Node provider middleware under [`server/providers`](https://github.com/bilawalsidhu/gods-eye-view/tree/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/server/providers), and a growing set of package exports declared in [`package.json`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/package.json). The strongest implementation idea is the separation between reusable browser/source/provider surfaces and the standalone app wiring. [`docs/CODE-BOUNDARIES.md`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/docs/CODE-BOUNDARIES.md) is unusually explicit about ownership boundaries, package exports, and build gates.

The weakness is also visible in the source: this is a big, highly stateful front-end system with many long modules, provider-specific branches, local credentials, public API fragility, and a lot of browser runtime behavior that only makes sense inside the full app. The builder lesson is still excellent: if a demo depends on live world data, treat feeds, caches, layer lifecycles, render budgets, attribution, and degraded states as first-class architecture.

## What they built
The product in [`README.md`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/README.md) is a local web app that starts without keys, then upgrades as users add provider credentials through the app. The core experience is a Cesium globe with optional photoreal 3D tiles, visual sensor styles, a HUD, live data overlays, tracking, cockpit view, share links, a scene director, and a realtime voice agent.

The concrete app entry point is small. [`src/main.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/main.js) creates a standalone application with browser-exposed Google Maps and Cesium tokens, starts it, and reports initialization failure into the loading screen. The real composition is in [`src/standalone/application.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/standalone/application.js), which wires four constructors into [`src/app/application.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/app/application.js): scene, controls, data, and tools.

The app's live-world surface comes from a registered data-layer catalog in [`src/standalone/data.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/standalone/data.js). That file registers flight, military flight, earthquake, satellite, rocket launch, traffic, CCTV, radio, bike-share, AIS vessel, military installation, military awareness, and bundled local layers through [`DataLayerManager`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/data/manager.js). The server side in [`server/providers/local.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/server/providers/local.js) registers the local Vite middleware that makes those feeds practical despite CORS, authentication, public-mirror failures, rate limits, and caching.

## Why it matters
This repo matters because it is a good example of a demo graduating into a messy product without hiding the mess. The README's most honest sentence is that most feeds are live or regularly refreshed, while traffic, camera poses, and launch trajectories are approximations. That is the correct posture for a system built on public signals.

Architecturally, the interesting point is that the app has to solve three hard problems at once. It needs a high-frame-rate 3D front end. It needs many unreliable data sources. It needs interaction flows that feel direct: click a plane, track it, enter cockpit view, project a public camera, jump to an ISS pass, ask the voice agent to manipulate layers, then serialize the state into a share link.

The source shows those problems are treated as systems problems. [`src/app/application.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/app/application.js) owns startup and teardown order. [`src/data/manager.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/data/manager.js) normalizes feed states and serializes layer visibility transitions. [`server/providers/common/http.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/server/providers/common/http.js) is exported as shared provider infrastructure. [`src/renderGovernor.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/renderGovernor.js) is used from [`src/standalone/tools.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/standalone/tools.js) so the globe can stop burning frames when nothing is animating.

## Layered architecture dissection
### High-level system shape
The app is a local browser console backed by local provider middleware. The browser owns Cesium rendering, interaction, layer lifecycle, voice actions, scene playback, and shareable state. The Node provider layer owns messy upstream access: request caps, authentication choices, proxy routes, rate limiting, cache behavior, and fallback data.

The boundary docs are not decorative. [`docs/APPLICATION.md`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/docs/APPLICATION.md) describes the four-constructor lifecycle contract. [`docs/CODE-BOUNDARIES.md`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/docs/CODE-BOUNDARIES.md) documents package exports and what each component owns. [`docs/INFRASTRUCTURE-LAYERS.md`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/docs/INFRASTRUCTURE-LAYERS.md) explains how reusable infrastructure layers receive an overlay host, context callbacks, and render scheduling from the consuming app.

### Main layers
**1. Application lifecycle layer**  
[`src/app/application.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/app/application.js) starts phases in the order `scene`, `controls`, `data`, `tools` and stops them in reverse. The `defer(cleanup)` contract is a good piece of engineering: constructors register cleanup immediately after acquiring resources, and startup failure still drains later-owned state.

**2. Scene and viewer layer**  
[`src/standalone/scene.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/standalone/scene.js) creates the Cesium viewer, attribution container, photoreal tile route, keyless globe fallback, and map-stack controller. It explicitly disables Cesium World Terrain when Google Photorealistic 3D Tiles are present because the tile source carries its own terrain/elevation surface.

**3. Controls and presentation layer**  
[`src/standalone/controls.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/standalone/controls.js) creates [`StyleManager`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/ui.js), camera presentation, and cockpit cloud effects. This keeps visual state and camera defaults outside the low-level application lifecycle.

**4. Data layer orchestration**  
[`src/data/manager.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/data/manager.js) is the layer transaction engine. It registers layer modules, seals production registrations, normalizes feed health labels, serializes toggles, distinguishes lifecycle state from settled visibility, keeps manager-owned refresh state, and protects explicit user/voice/tool intents from being overwritten by stale restoration.

**5. Layer implementation layer**  
Individual layer files do real domain work. [`src/data/flights.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/data/flights.js) uses billboard collections, dead reckoning, lerp correction, click-to-track, ground traffic handling, 3D model slots, and a long set of motion/model/altitude helpers. [`src/data/cctv.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/data/cctv.js) models cameras as catalogs, frustums, monitor planes, cards, health, calibration, and auto-hop. [`src/data/satellites.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/data/satellites.js) loads CelesTrak groups and propagates TLEs with `satellite.js`.

**6. Provider middleware layer**  
[`server/providers/local.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/server/providers/local.js) composes the local proxy. It imports provider modules such as [`server/providers/aircraft/opensky.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/server/providers/aircraft/opensky.js), [`server/providers/vessels/ais-live.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/server/providers/vessels/ais-live.js), [`server/providers/space/celestrak.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/server/providers/space/celestrak.js), [`server/providers/terrain.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/server/providers/terrain.js), and [`server/providers/traffic.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/server/providers/traffic.js). The comment header lists the actual live-feed responsibilities rather than hiding them behind "backend."

**7. Voice and tool-control layer**  
[`src/voice/gevRealtime.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/voice/gevRealtime.js) handles Realtime setup, push-to-talk, connection state, radio handoff, viewport screenshot limits, spend tier persistence, and debug/error logging. [`src/voice/gevActions.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/voice/gevActions.js) maps model actions into layer visibility, camera movement, CCTV, radio, cockpit, annotations, entity tracking, and context reads.

**8. Capture and replay layer**  
[`src/scenes/director.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/scenes/director.js) is a deterministic scene playback engine for clip capture. It stores shot lists, camera positions, style state, HUD state, detection overlay state, and layer toggles, then plays them back with timed flights and holds.

### Request / data / control flow
A normal page load starts at [`src/main.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/main.js), which calls [`createStandaloneApplication`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/standalone/application.js). [`createApplication`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/app/application.js) then constructs the scene, controls, data manager, and tools in order. The data phase registers layer modules through [`src/standalone/data.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/standalone/data.js), then the tools phase installs annotations, scene director, render governor, scope mask, hidden-tab suspension, debug handles, and voice commands through [`src/standalone/tools.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/standalone/tools.js).

When a user enables a layer, [`DataLayerManager`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/data/manager.js) owns the lifecycle transition and the layer module owns its domain-specific `init`, `enable`, `update`, `disable`, and `destroy` behavior. A layer such as [`src/data/flights.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/data/flights.js) pulls from a local endpoint, updates primitives, maintains tracking state, and asks the render governor for frames only when needed. The upstream HTTP details belong to provider modules behind routes registered by [`server/providers/local.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/server/providers/local.js).

When the user speaks, [`src/voice/gevRealtime.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/voice/gevRealtime.js) manages the Realtime session and routes model-requested actions to [`createGevActionRunner`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/voice/gevActions.js). The action runner normalizes aliases, refuses unknown layers, reports lifecycle summaries, cancels superseded work, and uses app services rather than poking the DOM directly.

## Important components
[`createApplication`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/app/application.js) is the cleanest reusable component. It does not know about Cesium, providers, credentials, or DOM layout. It knows construction order, abort, cleanup, state publication, and idempotent `start()`/`destroy()` behavior. That is the right extraction boundary.

[`DataLayerManager`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/data/manager.js) is the operational heart. The comments around toggle serialization are telling: without per-entry chains, a second toggle could interleave with initialization and arm duplicate polling intervals. That is exactly the kind of bug live-feed apps get if layer visibility is treated as a boolean instead of a transaction.

[`src/data/flights.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/data/flights.js) shows how much work sits below "show planes." It batches billboards, keeps local tangent-plane rotation, tracks selected aircraft with dead-reckoning callback positions, blends corrected fixes, handles grounded traffic, allocates 3D model slots under caps, and keeps the follow camera from fighting explicit navigation.

[`src/data/cctv.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/data/cctv.js) is the most delightful subsystem. It treats a traffic camera as a pose and projection problem: camera catalog, calibration offsets, frustum geometry, monitor plane, active frame refresh, ambient cards, and obstruction probing. That is much more interesting than embedding webcam thumbnails in a side panel.

[`src/voice/gevActions.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/voice/gevActions.js) is the model-to-app contract. It normalizes human words like "planes," "contacts," "data layers," "road map," and "satellite" into stable layer, panel, context, and map-stack IDs. It also handles cancellation and lifecycle summaries so the voice agent can report reality instead of claiming a layer turned on before it settled.

## Practical questions and answers
**Is this mostly a frontend demo?**  
No. The front end is the visible product, but [`server/providers/local.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/server/providers/local.js) and [`server/providers`](https://github.com/bilawalsidhu/gods-eye-view/tree/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/server/providers) are essential. Without proxying, capped reads, coalescing, caches, credential resolution, and source-specific fallbacks, the browser would mostly be a beautiful pile of failed requests.

**What file should a new contributor read first after the README?**  
Read [`docs/CODE-BOUNDARIES.md`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/docs/CODE-BOUNDARIES.md), then [`src/standalone/data.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/standalone/data.js). Those two explain the architecture better than starting inside a huge layer module.

**Where would production pain show up first?**  
Feed health and state races. The code already reflects that pain in [`src/data/manager.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/data/manager.js), where visibility intents, lifecycle uncertainty, stale/fallback/unavailable states, and refresh errors are separate concepts. The other pain point is provider quotas and public-service availability, visible in [`server/providers/local.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/server/providers/local.js).

**Is the voice layer just a chatbot bolted on top?**  
Not really. [`src/voice/gevActions.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/voice/gevActions.js) is a structured action runner with normalization, cancellation, lifecycle reads, and domain-specific handlers. The model is not meant to freestyle DOM clicks; it gets a constrained set of app actions.

**What would I avoid copying?**  
I would avoid copying the giant-module gravity. [`src/data/flights.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/data/flights.js), [`src/data/cctv.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/data/cctv.js), and [`src/voice/gevActions.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/voice/gevActions.js) are powerful, but their size and module-scoped state make local reasoning expensive.

## What is smart
- The app treats degraded data honestly. [`layerFeedState`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/data/manager.js) distinguishes loading, fallback, stale, degraded, unavailable, and nominal states.
- The startup contract in [`src/app/application.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/app/application.js) is small and reusable. It gives the rest of the app a clean place to hang cancellation and cleanup.
- The boundary system in [`docs/CODE-BOUNDARIES.md`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/docs/CODE-BOUNDARIES.md) and [`scripts/check-package-boundaries.mjs`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/scripts/check-package-boundaries.mjs) prevents reusable exports from quietly importing standalone globals.
- [`src/data/cctv.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/data/cctv.js) turns cameras into geometric objects in the world, not just media cards.
- [`src/standalone/tools.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/standalone/tools.js) suspends hidden-tab rendering and coordinates the render governor with tracking state, which is the kind of polish 3D browser apps need.
- The repo is test-heavy around things that usually rot: app lifecycle, layer policies, CCTV math, voice actions, provider proxies, boundaries, and QA browser probes.

## What is flawed or weak
- The codebase carries a lot of state in large modules. [`src/data/flights.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/data/flights.js), [`src/data/cctv.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/data/cctv.js), and [`src/voice/gevActions.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/voice/gevActions.js) are impressive but not easy to audit end to end.
- Local provider middleware in [`server/providers/local.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/server/providers/local.js) is doing many jobs at once: Overpass caching, credential stores, provider composition, regional data, radio, key setup, and more. The boundary docs admit future extractions are still pending.
- The app depends on public feeds and external provider terms. The README's keyless mode is real, but data coverage and freshness will still vary by service, geography, and rate limit.
- The credential story is local and pragmatic, not magical. [`README.md`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/README.md) says keys land in ignored local files or the Pinokio environment, which is appropriate for a local app but not a cloud security model.
- Node version requirements in [`package.json`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/package.json) are narrow enough that casual contributors may hit setup friction.

## What we can learn / steal
- Treat "live data layer" as a lifecycle transaction, not a checkbox. [`src/data/manager.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/data/manager.js) is worth copying conceptually for any map, dashboard, or monitoring UI.
- Put source-specific failure semantics in provider modules. [`server/providers`](https://github.com/bilawalsidhu/gods-eye-view/tree/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/server/providers) gives the browser a more stable surface than raw upstream APIs.
- Use geometry to make data feel native. The CCTV frustum and monitor-plane work in [`src/data/cctv.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/data/cctv.js) is a reusable idea: data overlays should inhabit the primary scene, not sit beside it.
- Create explicit package boundaries before the extraction is finished. [`docs/CODE-BOUNDARIES.md`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/docs/CODE-BOUNDARIES.md) gives contributors a migration map.
- For voice control, expose application actions, not generic DOM manipulation. [`src/voice/gevActions.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/voice/gevActions.js) is the right boundary between model intent and app state.

## How we could apply it
If we were building a live map or operations console, I would copy the `manager plus layer modules plus provider middleware` shape. The layer manager owns state transitions and presentation truth. Each layer owns its domain rendering and local cache. Provider modules own upstream weirdness. The UI only sees a stable set of controls and health states.

I would also copy the way [`src/app/application.js`](https://github.com/bilawalsidhu/gods-eye-view/blob/aacfa06a311f9eac2fe3cb37533ef08e43a3c7ac/src/app/application.js) forces ownership to be explicit. It is tempting to let a rich front-end app boot by importing a pile of modules with side effects. This repo is moving the other direction: inactive exports, caller-supplied constructors, cleanup registration, and boundary checks.

The other reusable idea is "make source uncertainty visible." Any dashboard that consumes public data should have first-class states for stale, fallback, degraded, and unavailable. Pretending everything is live because the demo looks alive is how operators learn to distrust the tool.

## Bottom line
`gods-eye-view` is worth studying because it shows the hidden architecture behind a viral geospatial demo. The visual layer is flashy, but the durable engineering is in layer lifecycles, feed adapters, provider caches, render-budget discipline, geometric CCTV projection, voice action contracts, and explicit package boundaries.

The repo is not small or perfectly tidy. It is better than that for study: it exposes the real compromises of a local, source-rich, live-data globe that wants to be fun without lying about how fragile the world data underneath it can be.
