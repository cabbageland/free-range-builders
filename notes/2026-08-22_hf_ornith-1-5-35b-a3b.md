## Executive summary
`Ornith-1.5-35B-A3B` is more interesting as a deployment artifact than as a benchmark brag sheet. The key files are concrete. [`chat_template.jinja`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/chat_template.jinja) shows the actual conversation grammar, including `<think>` reasoning traces, XML-style `<tool_call>` blocks, image/video placeholders, and strict role handling. [`config.json`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/config.json) exposes a Qwen3.5-MoE-derived multimodal model with a 40-layer text stack, 256 experts, 8 experts per token, a `full_attention_interval` of 4, and a 27-layer vision tower. [`processor_config.json`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/processor_config.json) and [`video_preprocessor_config.json`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/video_preprocessor_config.json) make the image/video ingestion contract explicit instead of burying it in prose.

The artifact matters because it does not stop at "here are some weights." [`README.md`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/README.md) tells you this is a reasoning model, specifies runtime minimums, shows the exact vLLM and SGLang flags for tool parsing and reasoning parsing, explains how to push past the 262,144-token native window with YaRN, and even includes OpenAI-compatible usage examples plus agent integration snippets for tools like OpenClaw and OpenCode. The package is trying to be operational, not merely aspirational.

The weakness is that the "self-improvement" story is mostly narrative in this artifact. The card talks about joint optimization of task generation, scaffold construction, and rollout improvement, but the Hugging Face package does not include the training harness, task generator, reward code, or rollout system. Builders can inspect the runtime contract extremely well, but they cannot reproduce the training claim from this artifact alone.

## Layered architecture dissection
### High-level system shape
The high-level shape is: serialize the conversation into a Qwen-style message grammar with explicit reasoning and tool-call markers, preprocess image/video inputs into visual tokens, run a multimodal MoE transformer with mostly linear attention and periodic full attention, and surface the result through an OpenAI-compatible server so standard agent frameworks can consume it.

### Main layers
**1. Product and runtime layer**  
[`README.md`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/README.md) is unusually operational. It specifies minimum runtime versions, recommended sampling ranges, `vllm serve` and `sglang.launch_server` commands, long-context override patterns, and direct examples for coding agents and OpenAI-compatible clients.

**2. Prompt and control-protocol layer**  
[`chat_template.jinja`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/chat_template.jinja) is the most important file. It defines how system/user/assistant/tool messages are serialized, how `<think>` blocks are preserved, how tools are advertised inside `<tools>...</tools>`, and how function calls must be emitted inside `<tool_call><function=...>` XML. [`tokenizer_config.json`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/tokenizer_config.json) backs that up with explicit special tokens like `<|vision_start|>`, `<|image_pad|>`, `<|video_pad|>`, and `<tool_call>`.

**3. Backbone layer**  
[`config.json`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/config.json) shows a 40-layer text model with `hidden_size: 2048`, `num_experts: 256`, `num_experts_per_tok: 8`, and a repeated `linear_attention` / `full_attention` schedule controlled by `full_attention_interval: 4`. This is not a plain dense checkpoint. It is explicitly a MoE reasoning model with a long native window of 262,144 tokens.

**4. Vision and preprocessing layer**  
The same [`config.json`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/config.json) carries a 27-layer vision stack. [`processor_config.json`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/processor_config.json) adds the runtime details: patch size 16, merge size 2, video frame sampling at 2 fps, `max_frames: 768`, and separate image/video processor types. This is the evidence that the artifact is genuinely multimodal, not just text-first branding.

**5. Packaging and inference layer**  
[`generation_config.json`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/generation_config.json) sets the baseline sampling defaults, while [`model.safetensors.index.json`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/model.safetensors.index.json) shows how the checkpoint is physically split across 16 shards totaling about 71.9 GB. The shard map is useful because it shows separate `model.language_model.*` and `model.visual.*` namespaces rather than one opaque blob.

### Inference / data / control flow
1. The caller formats system, user, assistant, and tool messages through [`chat_template.jinja`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/chat_template.jinja), with images and videos inserted as special pad tokens.
2. The tokenizer and processor layer, represented by [`tokenizer_config.json`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/tokenizer_config.json) and [`processor_config.json`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/processor_config.json), turns text/image/video content into the token and patch format expected by the model.
3. The multimodal MoE model described in [`config.json`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/config.json) performs reasoning over that serialized sequence.
4. Serving runtimes parse the model's `<think>` and `<tool_call>` outputs using the README's documented parser settings in [`README.md`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/README.md).
5. The result is surfaced through an OpenAI-compatible `/v1/chat/completions` endpoint, which is exactly why the card can show integrations for OpenClaw, OpenCode, Ollama-compatible flows, and other agent tools in [`README.md`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/README.md).

## Practical questions and answers
**Does the artifact really publish the tool-calling protocol?**  
Yes. [`chat_template.jinja`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/chat_template.jinja) spells out the XML envelope, and [`README.md`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/README.md) documents the parser settings required in vLLM and SGLang.

**Is the 1M-token context native?**  
No. [`config.json`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/config.json) exposes a native `max_position_embeddings` of 262,144. [`README.md`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/README.md) explains that longer windows come from YaRN scaling overrides.

**Is this only a text model?**  
No. [`config.json`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/config.json) includes a vision stack, and [`processor_config.json`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/processor_config.json) plus [`video_preprocessor_config.json`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/video_preprocessor_config.json) define actual image/video processing behavior.

**What does deployment look like in practice?**  
[`README.md`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/README.md) recommends recent vLLM or SGLang, tensor parallelism across 2x80 GB GPUs, explicit tool/reasoning parsers, and OpenAI-compatible serving on `/v1/chat/completions`.

**What would I read first to understand it fast?**  
Start with [`README.md`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/README.md), then [`chat_template.jinja`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/chat_template.jinja), [`config.json`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/config.json), [`processor_config.json`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/processor_config.json), and [`model.safetensors.index.json`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/model.safetensors.index.json).

## What is smart
- Publishing the exact reasoning and tool-call grammar in [`chat_template.jinja`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/chat_template.jinja) instead of hiding it behind SDK magic.
- Treating deployment as part of the release, with real runtime commands and parser flags in [`README.md`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/README.md).
- Exposing multimodal ingestion details in [`processor_config.json`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/processor_config.json), not just saying "supports images and video."
- Packaging the model behind an OpenAI-compatible endpoint story so it can drop into existing agent ecosystems quickly.

## What is flawed or weak
- [`README.md`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/README.md) spends a lot of surface area on benchmark theater and comparative positioning, while the claimed self-improvement pipeline is not inspectable from this artifact.
- The runtime contract depends on fairly specific parser support and runtime versions, which means the "just use the model" story is less universal than the card first suggests.
- The artifact is large and expensive: [`model.safetensors.index.json`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/model.safetensors.index.json) points to about 71.9 GB of bf16 weights, and [`README.md`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/README.md) recommends 2x80 GB GPUs for roomy 256K serving.
- The model card's big narrative claim is end-to-end self-improvement, but the downloadable artifact mainly proves inference-time usability, not the training mechanism behind it.

## What we can learn / steal
- If you want people to adopt a model for agent work, publish the exact tool grammar and parser assumptions.
- Put OpenAI-compatible serving examples directly in the card because that is the interoperability layer many builders already target.
- Document long-context caveats honestly; the YaRN note in [`README.md`](https://huggingface.co/ornith-ai/Ornith-1.5-35B-A3B/blob/main/README.md) is better than pretending 1M context is free.
- Make multimodal ingestion inspectable with processor configs instead of vague "supports images/video" claims.

## How we could apply it
If we were releasing our own agent-focused model, I would copy the operational transparency here. Ship the real chat template, the real runtime flags, the real context-extension caveats, and direct client examples for OpenAI-compatible consumers. I would not copy the benchmark-heavy presentation style. The reusable lesson is that inference ergonomics should be a first-class artifact, not a forum post afterthought.

## Bottom line
`Ornith-1.5-35B-A3B` is worth studying because it publishes the actual serving and interaction contract for a modern reasoning model instead of only publishing scores.

The strongest builder takeaway is simple: serious model releases should ship with wire protocol, parser assumptions, preprocessing rules, and deployment recipes visible in files. Ornith does that part well, even if the training-story proof is much thinner than the inference-story proof.
