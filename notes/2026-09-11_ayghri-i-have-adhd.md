## Executive summary
[`ayghri/i-have-adhd`](https://github.com/ayghri/i-have-adhd/tree/6f1f982d0a47c65899af3c5a7450b7098bc65325) is not a conventional app or model. It is a distribution package for a response-style policy: lead with the next action, number multi-step work, suppress tangents, restate state, make progress visible, and avoid pleasantries. The core product is the skill text in [`skills/i-have-adhd/SKILL.md`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/skills/i-have-adhd/SKILL.md), but the interesting engineering is around it: multiple plugin manifests, a Pi extension, OpenCode integration, Claude Code hooks, Codex plugin metadata, install docs, cross-platform tests, and an evaluation harness.

The repo's best idea is that style guidance needs runtime state. A one-off prompt can say "be concise"; this repo tries to make the mode persistent, toggleable, visible in the UI, recoverable after session compaction, and consistent across agent hosts. [`extensions/i-have-adhd.ts`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/extensions/i-have-adhd.ts) loads the rules once, strips frontmatter, stores enabled/disabled state as custom session entries, injects hidden rule messages only when needed, and writes a later disabled marker when the user exits the mode.

The weakness is that the repo is mostly behavior packaging around text, not a large software system. The durable lesson is still useful: if an agent behavior matters, treat it like software. Give it a single source of truth, adapters, install paths, compatibility shims, regression tests, and evals that test the claimed user benefit rather than the marketing slogan.

## What they built
The user-facing promise in [`README.md`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/README.md) is simple: install a skill/plugin that stops a coding assistant from burying the answer. The README's before/after example is not about shorter prose alone. It is about lowering execution friction: command first, numbered steps, one next action, no tangent, no "hope this helps."

The actual deliverable is a cross-agent package. [`package.json`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/package.json) declares an `i-have-adhd` private package with Pi and OMP extension entries pointing to [`extensions/i-have-adhd.ts`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/extensions/i-have-adhd.ts) and the [`skills`](https://github.com/ayghri/i-have-adhd/tree/6f1f982d0a47c65899af3c5a7450b7098bc65325/skills) directory. [`skills/i-have-adhd/SKILL.md`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/skills/i-have-adhd/SKILL.md) is marked `disable-model-invocation: true`, which is the right shape: this is not a tool the model calls, it is an instruction layer.

The repo also ships native surfaces for several ecosystems: Codex metadata in [`.codex-plugin/plugin.json`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/.codex-plugin/plugin.json), Claude Code metadata in [`.claude-plugin/plugin.json`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/.claude-plugin/plugin.json), Antigravity metadata in [`plugin.json`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/plugin.json), Gemini CLI metadata in [`gemini-extension.json`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/gemini-extension.json), OpenCode plugin code in [`.opencode/plugins/i-have-adhd.mjs`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/.opencode/plugins/i-have-adhd.mjs), and always-on hooks in [`hooks`](https://github.com/ayghri/i-have-adhd/tree/6f1f982d0a47c65899af3c5a7450b7098bc65325/hooks).

## Why it matters
This matters because a lot of agent customization is still distributed as snippets: paste this prompt, add this paragraph, remember to ask for this style. That does not survive real use. Users switch CLIs, sessions get compacted, plugins have marketplace manifests, hooks run on different platforms, and an "always on" mode needs a safe opt-out.

`i-have-adhd` is a useful example of turning a soft preference into a hard-ish product surface. The skill says the rules persist until "stop adhd mode" or "normal mode"; the Pi extension implements that through session state and input interception in [`extensions/i-have-adhd.ts`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/extensions/i-have-adhd.ts). The Claude hook path implements opt-in always-on behavior through [`hooks/always-on.mjs`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/hooks/always-on.mjs) and [`hooks/hooks.json`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/hooks/hooks.json). OpenCode mirrors the same single-source ruleset in [`.opencode/plugins/i-have-adhd.mjs`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/.opencode/plugins/i-have-adhd.mjs).

It is also a useful reminder that accessibility-oriented agent behavior should be tested against outcomes, not vibes. [`evals/RESULTS.md`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/evals/RESULTS.md) reports a first run over 14 cases and 3 trials: weighted score improved from 4.045 to 4.473, with gains concentrated in state reporting and error reporting. The same results file also names failures, including a `partial-success` regression and a broken `agent-owned-edit` case. That honesty is more valuable than a perfect-looking claim.

## Layered architecture dissection
### High-level system shape
The repo has a single source-of-truth instruction file surrounded by host adapters. The skill text defines the behavior. Runtime extensions decide when to inject it, how to persist the mode, and how to turn it off. Plugin manifests make the package discoverable in each ecosystem. Tests and evals keep the text and adapters from drifting.

The important point is that the instruction file alone is not treated as sufficient. Persistence is implemented in runtime state, not assumed by prose. Always-on mode is tied to local flag files, not an environment variable in a README. Cross-tool support gets its own manifests and tests rather than a paragraph saying "also works elsewhere."

### Main layers
**1. Policy layer**  
[`skills/i-have-adhd/SKILL.md`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/skills/i-have-adhd/SKILL.md) is the policy. It contains the persistence contract, the ten concrete output rules, explicit exceptions, and a pre-send checklist. The rules are behavioral and testable: "lead with the next action," "cap lists to 5 items," "matter-of-fact tone for errors," and "do not manufacture a diagnosis."

**2. Runtime state layer**  
[`extensions/i-have-adhd.ts`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/extensions/i-have-adhd.ts) turns the policy into mode state. It loads config from `i-have-adhd.json`, checks an `.i-have-adhd-always` flag, registers an `adhd` startup flag, registers `/i-have-adhd`, appends custom state entries, and intercepts input for `/skill:i-have-adhd`, `stop adhd mode`, and `normal mode`.

**3. Context synchronization layer**  
[`extensions/context-compat.ts`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/extensions/context-compat.ts) exists because runtime context APIs can change. It tries `buildSessionContext()` first, then `buildContextEntries()`, and falls back to an empty list on errors. [`latestMarkerIsActive`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/extensions/context-compat.ts) walks custom messages so a later disabled marker cancels an earlier active marker. That is a small but serious compaction-aware design.

**4. Host packaging layer**  
The same policy is wrapped for different tools. [`.codex-plugin/plugin.json`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/.codex-plugin/plugin.json) includes interface metadata, default prompts, logo paths, capabilities, and the `skills` path. [`.claude-plugin/plugin.json`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/.claude-plugin/plugin.json) is much smaller, because that host needs less manifest surface. [`gemini-extension.json`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/gemini-extension.json) points Gemini at [`GEMINI.md`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/GEMINI.md). [`.opencode/plugins/i-have-adhd.mjs`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/.opencode/plugins/i-have-adhd.mjs) registers skill paths and a command entry.

**5. Always-on hook layer**  
[`hooks/hooks.json`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/hooks/hooks.json) wires a `SessionStart` hook for startup, resume, clear, and compact. It imports [`hooks/always-on.mjs`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/hooks/always-on.mjs), which checks an opt-in flag, resolves `SKILL.md` relative to the script, strips YAML frontmatter, prints the rules, and exits 0 on failure so session start is never blocked.

**6. Evaluation and regression layer**  
[`evals/cases.jsonl`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/evals/cases.jsonl) contains cases such as `direct-answer`, `agent-owned-edit`, `debugging-cause`, `destructive-action`, `real-ambiguity`, `partial-success`, and `medical-boundary`. [`evals/rubric.md`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/evals/rubric.md) scores correctness, autonomy, actionability, safety, and concision. [`scripts/run_evals.py`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/scripts/run_evals.py) enforces paired conditions, cost reporting, release gates, and neutral working directories.

### Request / data / control flow
On a Pi-style host, the user can enable the mode by startup flag, config, always-on flag, `/i-have-adhd`, or `/skill:i-have-adhd`. [`iHaveAdhdExtension`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/extensions/i-have-adhd.ts) loads the skill, restores state on `session_start` and `session_tree`, and calls `syncContext`. If enabled and no active marker is present, it sends a hidden custom rules message. If disabled while a rules marker is present, it sends a hidden disabled notice. On `session_compact`, it syncs again because compaction may remove the injected message.

On Claude-style always-on mode, [`hooks/hooks.json`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/hooks/hooks.json) runs at session start and resume. [`hooks/always-on.mjs`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/hooks/always-on.mjs) checks the opt-in flag under the Claude config dir, reads the skill, strips frontmatter, and writes the rules to stdout. The host then includes that output as session-start context.

On OpenCode, [`.opencode/plugins/i-have-adhd.mjs`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/.opencode/plugins/i-have-adhd.mjs) adds the skill directory to `config.skills.paths`, tries to register the command metadata from [`.opencode/command/i-have-adhd.md`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/.opencode/command/i-have-adhd.md), and appends the stripped ruleset to the system prompt while an OpenCode-specific flag file exists.

## Important components
The skill file is more operational than it first appears. [`skills/i-have-adhd/SKILL.md`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/skills/i-have-adhd/SKILL.md) does not only say "be concise." It encodes when to break the rules: explain fully when asked, confirm destructive actions, stop after debug spirals, ask one blocking question on real ambiguity, and let harness/system constraints win. Those exceptions make it less likely to damage autonomy or safety.

[`extensions/i-have-adhd.ts`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/extensions/i-have-adhd.ts) is the most important source file. It defines marker types (`i-have-adhd-state`, `i-have-adhd-rules`, `i-have-adhd-disabled`), UI status, stop phrases, rule loading, saved-state restoration, and event handlers. The mode is not just a prompt prefix; it is a small state machine.

[`extensions/context-compat.ts`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/extensions/context-compat.ts) is a good defensive component. Its failure behavior is to return no messages, which causes the caller to reinject rules instead of breaking session startup. For this kind of plugin, duplicate hidden instructions are annoying; broken startup is worse.

[`scripts/run_evals.py`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/scripts/run_evals.py) is more serious than a toy benchmark runner. It validates case shape, enforces matched baseline/candidate rows, computes weighted scores, rejects unmetered runners unless allowed, uses a neutral scratch working directory so the repo itself does not contaminate model behavior, and encodes release-gate reasons.

The CI workflows are small but pointed. [`.github/workflows/plugin-load-check.yml`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/.github/workflows/plugin-load-check.yml) installs Claude Code, adds this checkout as a plugin marketplace, installs the plugin, and greps for enabled state. [`.github/workflows/pi-load-check.yml`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/.github/workflows/pi-load-check.yml) installs Pi and runs [`scripts/check_pi_extension.py`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/scripts/check_pi_extension.py).

## Important knobs / configs / extension points
- [`i-have-adhd.json`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/extensions/i-have-adhd.ts) is read from the agent dir by the Pi extension; supported keys include `alwaysOn` and `hideStatus`.

- Always-on mode uses flag files: Claude uses `.i-have-adhd-always` under the Claude config dir in [`hooks/always-on.mjs`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/hooks/always-on.mjs), while OpenCode uses `.config/opencode/.i-have-adhd-always` in [`.opencode/plugins/i-have-adhd.mjs`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/.opencode/plugins/i-have-adhd.mjs).
- The rules themselves are meant to be forked and edited in [`skills/i-have-adhd/SKILL.md`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/skills/i-have-adhd/SKILL.md), with retuning instructions in [`README.md`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/README.md).
- Eval cases are extensible through [`evals/cases.jsonl`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/evals/cases.jsonl), while model runners are configured with [`evals/runners.example.json`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/evals/runners.example.json).

## Practical questions and answers
**Is this just a prompt pack?**  
No. The core is prompt-like, but the repo treats it as a package. The important software is in [`extensions/i-have-adhd.ts`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/extensions/i-have-adhd.ts), [`hooks/always-on.mjs`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/hooks/always-on.mjs), [`.opencode/plugins/i-have-adhd.mjs`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/.opencode/plugins/i-have-adhd.mjs), and the CI/eval files that keep behavior loadable and measurable.

**What is the most reusable pattern?**  
Use a single instruction file as the source of truth, then strip frontmatter and inject that same body in every host adapter. The repo repeats this pattern in [`extensions/i-have-adhd.ts`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/extensions/i-have-adhd.ts), [`hooks/always-on.mjs`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/hooks/always-on.mjs), and [`.opencode/plugins/i-have-adhd.mjs`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/.opencode/plugins/i-have-adhd.mjs).

**Where could it fail in production use?**  
Host APIs change. That is why [`extensions/context-compat.ts`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/extensions/context-compat.ts) exists. Another failure mode is over-constraining the model: [`evals/RESULTS.md`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/evals/RESULTS.md) calls out a `partial-success` case where the candidate may have asserted a cause too strongly.

**Does the repo claim this diagnoses ADHD?**  
No. [`README.md`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/README.md) says "No ADHD diagnosis needed," and [`evals/cases.jsonl`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/evals/cases.jsonl) includes a `medical-boundary` case requiring the model to say the style cannot diagnose ADHD.

## What is smart
- The repo names the actual product correctly: not "short answers," but action-first output for a reader with limited working memory.
- [`extensions/i-have-adhd.ts`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/extensions/i-have-adhd.ts) uses hidden custom messages and disabled markers instead of repeatedly stuffing visible prompts into every turn.
- [`hooks/always-on.mjs`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/hooks/always-on.mjs) resolves paths relative to the script and exits 0 on failure, which is the right failure mode for a session-start hook.
- [`evals/README.md`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/evals/README.md) explicitly warns about contamination from user-level plugins, hooks, memory, output styles, model defaults, and the repo's own always-on flag.
- [`evals/RESULTS.md`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/evals/RESULTS.md) publishes uncomfortable findings instead of turning one positive aggregate score into a victory lap.

## What is flawed or weak
- The repo's power still comes from instruction following. A weaker model or a host that mangles hidden context can ignore or partially apply the policy.
- Cross-host support means many manifests can drift. [`.codex-plugin/plugin.json`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/.codex-plugin/plugin.json), [`.claude-plugin/plugin.json`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/.claude-plugin/plugin.json), [`gemini-extension.json`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/gemini-extension.json), and [`.opencode/plugins/i-have-adhd.mjs`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/.opencode/plugins/i-have-adhd.mjs) all express related but not identical behavior.
- The eval set is thoughtful but small. [`evals/RESULTS.md`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/evals/RESULTS.md) says three trials is few and that single-case deltas below roughly 0.5 should not be treated as signal.
- The release gate failed in the published run. That does not make the project bad, but it means the current evidence says "promising and useful," not "formally safe."

## What we can learn / steal
- Treat response style as a feature with state, install surfaces, tests, and evals. Do not leave important agent behavior as a pasteable paragraph.
- Use a single source of truth for the rules, as [`skills/i-have-adhd/SKILL.md`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/skills/i-have-adhd/SKILL.md) does, then have every adapter load that file.
- Add explicit escape hatches. The "when to break the rules" section in [`SKILL.md`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/skills/i-have-adhd/SKILL.md) is why the style can stay concise without deleting safety, ambiguity handling, or long-form explanations.
- Test host loading, not just syntax. The plugin load workflow in [`.github/workflows/plugin-load-check.yml`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/.github/workflows/plugin-load-check.yml) catches failures a schema checker would miss.
- Benchmark the actual claimed effect. [`evals/rubric.md`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/evals/rubric.md) weights correctness and autonomy above concision, which prevents the skill from winning by merely becoming shorter.

## How we could apply it
For our own reusable agent preferences, I would copy the "policy file plus adapters" shape. A builder note style, code-review style, or production-debugging style should live in one instruction file, then get thin adapters for each host. The adapters should handle persistence, status, compaction, and opt-out instead of asking the model to remember everything forever.

I would also copy the eval discipline. Start with a case file like [`evals/cases.jsonl`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/evals/cases.jsonl), score against correctness/autonomy/actionability/safety/concision, and publish the failures. Style changes can look good while quietly damaging tool use or ambiguity handling; a paired baseline/candidate harness like [`scripts/run_evals.py`](https://github.com/ayghri/i-have-adhd/blob/6f1f982d0a47c65899af3c5a7450b7098bc65325/scripts/run_evals.py) is the right guardrail.

## Bottom line
`i-have-adhd` is worth studying because it turns a small instruction idea into a portable agent-behavior package. The repo is not deep in algorithms, but it is unusually concrete about runtime state, host adapters, opt-in flags, stop phrases, compaction, CI, and eval contamination.

The biggest lesson is that useful agent behavior deserves software treatment. If the behavior should persist, toggle, survive context changes, and work across hosts, then it needs code, tests, and evals around the text.
