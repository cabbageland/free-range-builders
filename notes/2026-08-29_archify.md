## Executive summary
[`Archify`](https://github.com/tt-a1i/archify/tree/0853a805003514776bef3593ecca091409828902) is best understood as a deterministic compiler around agent-authored diagram JSON, not as a drawing tool and not as a loose chat plugin. The root [`README.md`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/README.md) sells the product in glossy language, but the real substance lives in the nested [`archify`](https://github.com/tt-a1i/archify/tree/0853a805003514776bef3593ecca091409828902/archify) package.

The command surface in [`archify/bin/archify.mjs`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/archify/bin/archify.mjs) makes the system shape clear: `render`, `validate`, `compare`, `deliver`, `preview`, `inspect`, `check`, `visual-check`, `guide`, `brands`, and `demo` are first-class commands. That is a builder signal. The team is treating diagram generation as a checked artifact pipeline with explicit stages, not as "ask the model again and hope."

The most interesting engineering move is the way trust is layered. [`archify/renderers/shared/validator.mjs`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/archify/renderers/shared/validator.mjs) turns schema failures into annotated, path-aware diagnostics instead of raw validator spew. [`archify/bin/preview.mjs`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/archify/bin/preview.mjs) keeps a loopback-only preview shell and refuses to replace the displayed artifact until a new revision verifies. [`archify/renderers/shared/repository-evidence.mjs`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/archify/renderers/shared/repository-evidence.mjs) goes further by checking origin URL, full commit SHA, repo-relative paths, and optional line ranges before evidence-backed architecture nodes are rendered.

The weak side is packaging and scope clarity. The outer repo is heavy on marketing, screenshots, and generated assets, while the actual product is tucked into a nested package plus a ZIP bundle. The evidence system is also narrower than the product page vibe suggests: it currently applies to architecture diagrams only, assumes public GitHub repos, requires a full 40-character SHA, and needs a matching local checkout for verification.

## What they built
They built a diagram-generation system for agents that turns typed JSON into self-contained HTML/SVG artifacts, with five primary modes called out directly in [`archify/bin/archify.mjs`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/archify/bin/archify.mjs): architecture, workflow, sequence, dataflow, and lifecycle.

The practical product loop is laid out across the source:

- [`archify/schemas/architecture.schema.json`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/archify/schemas/architecture.schema.json) and sibling schemas define the authored IR shape.
- [`archify/renderers/architecture/render-architecture.mjs`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/archify/renderers/architecture/render-architecture.mjs) and the other renderer folders compile that IR into layouted diagrams.
- [`archify/delta/architecture-delta.mjs`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/archify/delta/architecture-delta.mjs) adds explicit before/delta/after comparison.
- [`archify/bin/preview.mjs`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/archify/bin/preview.mjs) adds a live authoring loop that preserves the last verified output through failures.

## Why it matters
Most AI-generated diagrams are untrustworthy because the model directly emits presentation markup. Archify inserts a compiler boundary.

1. The authored object is structured JSON, not freehand SVG.
2. Validation is explicit and fail-closed through [`archify/renderers/shared/validator.mjs`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/archify/renderers/shared/validator.mjs).
3. Rendering is type-specific, with separate geometry and layout logic in [`archify/renderers/architecture`](https://github.com/tt-a1i/archify/tree/0853a805003514776bef3593ecca091409828902/archify/renderers/architecture) and shared primitives in [`archify/renderers/shared`](https://github.com/tt-a1i/archify/tree/0853a805003514776bef3593ecca091409828902/archify/renderers/shared).
4. Repository evidence is verified against pinned source instead of being a decorative citation layer.

That combination is the real builder lesson: treat model output as IR that must survive deterministic checks before it becomes something users trust.

## Layered architecture dissection
### High-level system shape
The high-level flow is: an agent or human authors a typed JSON diagram, the CLI dispatches to a renderer based on diagram type, shared validation and diagnostics gate the input, the renderer computes geometry and presentation, and preview or deliver commands publish only checked output.

### Main layers
**1. Command and orchestration layer**  
[`archify/bin/archify.mjs`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/archify/bin/archify.mjs) is the top control surface. It resolves diagram type, quality profile, repo-root evidence mode, compare mode, and preview mode.

**2. Schema and diagnostic layer**  
[`archify/schemas`](https://github.com/tt-a1i/archify/tree/0853a805003514776bef3593ecca091409828902/archify/schemas) defines the contracts. [`archify/renderers/shared/validator.mjs`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/archify/renderers/shared/validator.mjs) imports generated validators and upgrades plain AJV failures into subject-aware diagnostics with suggested fixes.

**3. Rendering and layout layer**  
[`archify/renderers/architecture/render-architecture.mjs`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/archify/renderers/architecture/render-architecture.mjs) is not a thin wrapper. It imports custom geometry, legend, readability, grid placement, route-cleanup, and label-clearance helpers from shared modules like [`geometry.mjs`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/archify/renderers/shared/geometry.mjs), [`layout-report.mjs`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/archify/renderers/shared/layout-report.mjs), and [`text-fit.mjs`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/archify/renderers/shared/text-fit.mjs).

**4. Evidence and comparison layer**  
[`archify/renderers/shared/repository-evidence.mjs`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/archify/renderers/shared/repository-evidence.mjs) verifies Git origin, pinned revision, repo-relative source paths, and optional line ranges. [`archify/delta/architecture-delta.mjs`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/archify/delta/architecture-delta.mjs) handles explicit architecture diffing instead of treating change review as an afterthought.

**5. Preview and delivery layer**  
[`archify/bin/preview.mjs`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/archify/bin/preview.mjs) wraps rendering in a loopback-only HTTP server with SSE state updates and a last-good artifact buffer. That means failed revisions do not replace the currently trusted output.

### Request / data / control flow
1. The author produces JSON shaped by a schema such as [`architecture.schema.json`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/archify/schemas/architecture.schema.json).
2. [`archify/bin/archify.mjs`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/archify/bin/archify.mjs) chooses the relevant renderer and prepares quality or evidence flags.
3. The per-type renderer loads the diagram, computes positions, boundaries, routes, legend placement, and accessible presentation details.
4. Shared validation and artifact checks classify failures into structured diagnostics instead of renderer stack traces.
5. `deliver` writes the checked artifact, while `preview` serves only the most recent verified revision.

## Practical questions and answers
**Is this just a prettier Mermaid alternative?**  
No. The source points to a compiler-style pipeline with typed inputs, per-type renderers, validation gates, preview state management, and explicit compare/evidence stages.

**Where is the trust boundary?**  
In the combination of [`archify/schemas`](https://github.com/tt-a1i/archify/tree/0853a805003514776bef3593ecca091409828902/archify/schemas), [`validator.mjs`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/archify/renderers/shared/validator.mjs), artifact checks wired through [`archify/bin/archify.mjs`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/archify/bin/archify.mjs), and source verification in [`repository-evidence.mjs`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/archify/renderers/shared/repository-evidence.mjs).

**What is the sharpest implementation idea here?**  
The last-good preview model in [`archify/bin/preview.mjs`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/archify/bin/preview.mjs). It treats invalid generations as diagnostics, not as something that should replace the current artifact.

**Where does the system look brittle?**  
The repo layout is a little confusing, the product framing is louder than the package structure, and repository evidence has several operational constraints that users may not anticipate from the README alone.

## What is smart
- Treating model output as typed IR instead of direct presentation markup.
- Converting schema errors into repairable diagnostics with identity hints in [`validator.mjs`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/archify/renderers/shared/validator.mjs).
- Keeping preview pinned to the last verified artifact in [`preview.mjs`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/archify/bin/preview.mjs).
- Verifying source evidence against repo origin, pinned SHA, and actual blob paths in [`repository-evidence.mjs`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/archify/renderers/shared/repository-evidence.mjs).
- Making architecture diffing an explicit subsystem via [`architecture-delta.mjs`](https://github.com/tt-a1i/archify/blob/0853a805003514776bef3593ecca091409828902/archify/delta/architecture-delta.mjs).

## What is flawed or weak
- The root repo presentation is louder than the core code, so the serious part is easy to miss.
- The real package is nested under [`archify`](https://github.com/tt-a1i/archify/tree/0853a805003514776bef3593ecca091409828902/archify), which is slightly awkward for first-time readers.
- Repository evidence is powerful but narrow: architecture-only, GitHub-only, full-SHA-only, and dependent on a matching local checkout.
- The source surface is already fairly broad for a young tool, which means maintenance pressure will not stay trivial.

## What we can learn / steal
- Put a deterministic compiler between model output and user-visible artifacts.
- Make failed generations produce structured repair receipts, not raw stack traces.
- Keep a last-known-good artifact in interactive preview flows.
- If you claim source grounding, verify the source against pinned revisions instead of trusting authored citations.

## How we could apply it
If we were building any AI-assisted artifact generator, I would copy the core pattern here almost directly: typed IR, explicit schemas, structured diagnostics, and a preview that only advances on verified output. I would simplify the repo packaging, but the trust model is the real prize.

## Bottom line
`Archify` looks flashy on the surface, but the source reveals a more serious idea underneath: AI output should be compiled, checked, and optionally evidence-verified before it becomes a deliverable.

The builder takeaway is simple and reusable. Do not let the model write the final artifact directly if users are going to trust it.
