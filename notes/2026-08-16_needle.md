The repository contains a real schema compiler, a JAX reference stack, a deployable runtime contract, and a CLI that makes the "14MB tool model" claim concrete enough to study.

## Executive summary
`needle` is a compact but unusually complete small-model product. The top-level user contract lives in [`needle/__init__.py`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/__init__.py), where the `Needle` class binds tool schemas, loads optional `.cact` weights, calls the native engine through `ctypes`, and loops tool execution back into the model. The schema layer in [`needle/agent/tools.py`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/agent/tools.py) is equally important: Python signatures, docstrings, `Literal`s, and `Field(...)` constraints are compiled into JSON Schema instead of being hand-waved as prompt text.

The real engineering weight sits in the reference model stack under [`needle/model`](https://github.com/cactus-compute/needle/tree/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/model). [`architecture.py`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/model/architecture.py) shows a Simple Attention Network with engram memory, multi-lane hyper-connections, a contrastive retrieval head, and a separate confidence head. [`decode.py`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/model/decode.py) adds cached decoding and an explicit KV-budget window. [`finetune.py`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/model/finetune.py) then turns that into a practical loop with LoRA, synthetic data generation, and export.

The smartest move is that the project treats tool calling as the whole product surface, not as a sidecar feature. The biggest weakness is that the production tiny-device runtime itself is fetched as a binary through [`needle/__init__.py`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/__init__.py) and the CLI's [`fetch` path](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/cli.py), so the part most central to the "runs in 28MB RAM" story is not fully inspectable in-source here.

## What they built
They built a small local tool-calling stack with four real surfaces:

- A Python agent API in [`needle/__init__.py`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/__init__.py) for `complete()`, `run()`, `extract()`, and `reset()`.
- A schema compiler in [`needle/agent/tools.py`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/agent/tools.py) that turns functions, Pydantic models, and raw schemas into a constrained tool interface.
- A reference research and training stack in [`needle/model/architecture.py`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/model/architecture.py), [`needle/model/decode.py`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/model/decode.py), [`needle/model/run.py`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/model/run.py), and [`needle/model/finetune.py`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/model/finetune.py).
- Product and operator surfaces in [`needle/cli.py`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/cli.py), the browser playground under [`needle/playground`](https://github.com/cactus-compute/needle/tree/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/playground), and the usage docs in [`doc/apis.md`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/doc/apis.md).

## Why it matters
Tiny local models are often sold as demos that can barely survive contact with real tool contracts. `needle` matters because the repository is organized around the opposite thesis:

1. Tool schemas are a hard boundary, not a soft suggestion.
2. Retrieval is built into the model contract for larger tool catalogs.
3. Confidence is a first-class output, not an afterthought.
4. Offline deployment is treated as a packaging problem, not just a benchmark slide.

## Layered architecture dissection
### High-level system shape
The high-level shape is: take Python or JSON tool declarations, compile them into a bounded schema set, initialize a native engine with those schemas, decode only valid tool calls, execute those calls in Python, then feed structured results back into the loop. Separately, the repo carries a JAX reference stack that can train, calibrate, and export weights into the `.cact` format the runtime consumes.

### Main layers
**1. Schema and contract layer**  
[`needle/agent/tools.py`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/agent/tools.py) is where the repo becomes a system rather than a wrapper. `build_schema()` extracts descriptions from docstrings, maps type hints into JSON types, preserves `Literal` choices, and applies `Field(...)` constraints like ranges, regexes, and item counts directly to the schema.

**2. Runtime and loop layer**  
[`needle/__init__.py`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/__init__.py) wires the product together. `_library_path()` resolves or fetches the native engine, `_lib()` binds `needle_init`, `needle_complete`, `needle_reset`, and `needle_load`, `complete()` returns a JSON object from the engine, and `run()` executes local Python functions until the model stops emitting calls.

**3. Model architecture layer**  
[`needle/model/architecture.py`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/model/architecture.py) contains the actual research shape. `SimpleAttentionNetwork` combines a token embedding stack, engram memory sites, a contrastive head for tool retrieval, and a separate confidence head for acceptance gating. That is more ambitious than "mini model does JSON."

**4. Decode and memory-budget layer**  
[`needle/model/decode.py`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/model/decode.py) explains how they keep the model bounded. The file builds cached attention paths, explicit KV caches, engram lookups, and a computed window budget via `kv_budget_window()` and `effective_kv_window()`.

**5. Tuning and productization layer**  
[`needle/model/finetune.py`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/model/finetune.py) is not just training glue. It serializes examples into the model's tool-call format, supports LoRA on selected kernels, optionally generates synthetic examples through OpenRouter, and exports tuned checkpoints back into the runtime's deployment format. [`needle/cli.py`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/cli.py) exposes that whole path as `run`, `finetune`, `generate-data`, `build`, `fetch`, `download`, and `playground`.

### Request / data / control flow
1. A builder decorates functions or passes schemas; [`build_schema()`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/agent/tools.py) turns them into JSON Schema.
2. [`Needle.__init__`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/__init__.py) resolves those schemas, binds optional weights, and initializes the native engine.
3. [`complete()`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/__init__.py) sends the user turn into the engine and receives structured JSON with `function_calls`, `reasoning`, and `confidence`.
4. [`run()`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/__init__.py) executes the selected Python functions, serializes their outputs, and feeds them back until the response is no longer a call.
5. For larger tool sets, the retrieval rules in [`doc/apis.md`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/doc/apis.md) and the contrastive head in [`architecture.py`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/model/architecture.py) reduce the grammar to the top five tools per turn.

## Important components
The most important component is the [`Needle` class](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/__init__.py). That file proves the product is not just a model card. It binds the engine, normalizes tools, handles tuned weights, and owns the multi-step execution loop.

The second is [`SimpleAttentionNetwork`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/model/architecture.py). The contrastive and confidence heads are structural choices, not README boasts.

The third is [`decode.py`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/model/decode.py), because small-model usability lives or dies on memory policy, not just perplexity.

The fourth is [`build_schema()`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/agent/tools.py), because the entire deterministic contract depends on schema quality.

## Practical questions and answers
**Is this mostly a wrapper around a binary blob?**  
Partly, yes. [`needle/__init__.py`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/__init__.py) clearly fetches and binds a native library, so the production runtime is less inspectable than the JAX research code.

**Does the repo still contain meaningful model internals?**  
Yes. [`architecture.py`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/model/architecture.py) and [`decode.py`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/model/decode.py) contain enough real implementation to study the memory, retrieval, and confidence story.

**What is the key product constraint?**  
[`doc/apis.md`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/doc/apis.md) makes it explicit: this system treats tool calls as the only answer surface. Unsupported inputs return `[]`; there is no graceful free-text fallback.

**What is the most production-relevant gotcha?**  
Fine-tuning does not retune the confidence head. Both [`doc/apis.md`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/doc/apis.md) and [`Needle.__init__`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/__init__.py) make clear that tuned agents report `confidence=None`.

## What is smart
- Turning Python signatures and docstrings into a real schema boundary in [`needle/agent/tools.py`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/agent/tools.py).
- Shipping retrieval and calibration as structural heads in [`architecture.py`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/model/architecture.py) instead of pretending prompt wording will solve everything.
- Treating offline deployment as a first-class product path through [`needle/cli.py`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/cli.py) and [`doc/apis.md`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/doc/apis.md).
- Keeping the public API small while still exposing training, export, playground, and fetch flows.

## What is flawed or weak
- The runtime sold as the deployable core is fetched native code, so the most commercially important layer is the least transparent.
- The product contract is intentionally narrow: tool call or empty call. That is clean for safety, but brittle if you need mixed natural-language UX.
- Confidence disappears for tuned weights, which weakens one of the repo's strongest original claims.
- The synthetic-data path in [`finetune.py`](https://github.com/cactus-compute/needle/blob/c152cc4d9821a002285f85aaf58876c6d60541fe/needle/model/finetune.py) depends on OpenRouter and defaults to a hosted model, which is practical but undercuts the otherwise self-contained story.

## What we can learn / steal
- Make the tool schema the real interface, not a prose suggestion hidden inside prompts.
- Use retrieval to shrink the live grammar instead of stuffing every tool into context every turn.
- Separate the research stack from the deployment engine while keeping the exported format stable.
- Be explicit about when confidence is calibrated and when it is not.

## How we could apply it
If we wanted a local or edge agent path, I would copy the contract design more than the exact model. A strong schema compiler, a top-k tool selection pass, a hard act-or-escalate threshold, and an offline packaging story are all reusable. I would be more transparent than this repo about the native runtime internals, but the interface discipline is worth stealing.

## Bottom line
`needle` is worth studying because it is not just a tiny model with a flashy size claim. It is a compact attempt to turn small-model tool calling into an end-to-end product contract.

The builder lesson is that determinism, retrieval, and packaging matter more than raw parameter count. The caveat is that the repo's deployable magic still hides in a fetched native engine, so admiration should stay mixed with skepticism.
