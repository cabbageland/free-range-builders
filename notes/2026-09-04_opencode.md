# OpenCode

- Repo: `anomalyco/opencode`
- URL: https://github.com/anomalyco/opencode
- Date: 2026-09-04
- Repo snapshot studied: `dev` @ `51f86c853791c41656fb0adcf9413291e4996b87`
- Why picked today: GitHub's live trending page included `anomalyco/opencode` on September 4, 2026, and the repo metadata showed 203,898 stars and 26,609 forks when checked. More importantly, the source is clearly not a thin "AI CLI" wrapper. It is a large monorepo with a provider-neutral LLM core, a separate session/tool engine, multiple frontends, plugin loading, MCP integration, and a heavy automated test surface.

## Executive summary
[`OpenCode`](https://github.com/anomalyco/opencode/tree/51f86c853791c41656fb0adcf9413291e4996b87) is best understood as a product platform for coding agents, not as one terminal app. The root [`package.json`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/package.json) lays out the monorepo split immediately: the workspace contains many packages, but the real agent runtime sits in [`packages/opencode`](https://github.com/anomalyco/opencode/tree/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode), while the provider-neutral transport layer lives in [`packages/llm`](https://github.com/anomalyco/opencode/tree/51f86c853791c41656fb0adcf9413291e4996b87/packages/llm).

The strongest engineering decision is the hard separation between "talk to model providers" and "run an agent session." [`packages/llm/README.md`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/llm/README.md) describes a schema-first request/event/tool layer that normalizes OpenAI, Anthropic, Gemini, Bedrock, and OpenAI-compatible backends. Then [`packages/opencode/src/session/prompt.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/session/prompt.ts), [`packages/opencode/src/session/processor.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/session/processor.ts), and [`packages/opencode/src/session/tools.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/session/tools.ts) build the actual agent loop on top.

The most builder-useful detail is that the runtime is defensive in unglamorous places. [`processor.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/session/processor.ts) captures a filesystem snapshot before streaming begins because tools may execute before the first visible stream event. [`packages/opencode/src/tool/registry.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/tool/registry.ts) assembles built-in, plugin, MCP, LSP, and optional code-mode tools behind one registry boundary. [`packages/opencode/src/plugin/loader.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/plugin/loader.ts) even distinguishes install, entrypoint, compatibility, and load failures so plugin problems are explainable instead of mysterious.

The weak side is repo sprawl. There is a lot of real engineering here, but also a lot of surface area: infra, web, desktop, GitHub action packaging, specs, artifacts, and some confusing leftovers such as the generic template-like [`packages/app/README.md`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/app/README.md). The serious system is there, but first-time readers have to find it.

## What they built
They built an open-source coding-agent stack with several shells around one core runtime:

- The top-level binary and command surface are wired through [`packages/opencode/src/index.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/index.ts) and the CLI wrapper in [`packages/cli/src/index.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/cli/src/index.ts).
- Session state, prompts, compaction, retries, tool execution, and history live under [`packages/opencode/src/session`](https://github.com/anomalyco/opencode/tree/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/session).
- The HTTP server layer lives in [`packages/opencode/src/server`](https://github.com/anomalyco/opencode/tree/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/server), while the shared public API contract is exposed from [`packages/server/src/api.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/server/src/api.ts).
- The terminal UI lives in [`packages/tui`](https://github.com/anomalyco/opencode/tree/51f86c853791c41656fb0adcf9413291e4996b87/packages/tui), and the web-oriented surfaces and tests spread across [`packages/app`](https://github.com/anomalyco/opencode/tree/51f86c853791c41656fb0adcf9413291e4996b87/packages/app) and related packages.

## Why it matters
Most agent products entangle prompt logic, provider quirks, UI, and tool execution into one impossible knot. OpenCode splits them.

1. Provider differences are pushed down into [`packages/llm/src/providers`](https://github.com/anomalyco/opencode/tree/51f86c853791c41656fb0adcf9413291e4996b87/packages/llm/src/providers) and [`packages/llm/src/protocols`](https://github.com/anomalyco/opencode/tree/51f86c853791c41656fb0adcf9413291e4996b87/packages/llm/src/protocols).
2. Agent behavior is concentrated in [`packages/opencode/src/session`](https://github.com/anomalyco/opencode/tree/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/session) and [`packages/opencode/src/tool`](https://github.com/anomalyco/opencode/tree/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/tool).
3. Runtime integration points like plugins and MCP are explicit subsystems, not hidden hacks.

That makes the project more reusable than most "ship a coding agent fast" repos.

## Layered architecture dissection
### High-level system shape
The control flow is: CLI or UI entrypoint starts a session, session prompt assembly chooses model-specific system text and tool surface, the LLM streams provider-neutral events, tool calls are tracked as structured session parts, and the server or TUI projects the live state outward.

### Main layers
**1. Entry and shell layer**  
[`packages/opencode/src/index.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/index.ts) and [`packages/cli/src/index.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/cli/src/index.ts) expose commands, service control, API mode, MCP, sessions, plugins, web, and provider management.

**2. Session orchestration layer**  
[`packages/opencode/src/session/prompt.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/session/prompt.ts) is the orchestration hub. It resolves prompt parts, titles, permissions, MCP, compaction, retries, structured output, and subtask handling. [`packages/opencode/src/session/system.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/session/system.ts) chooses different prompt templates for GPT, Codex, Gemini, Claude, Kimi, Trinity, and Meta-like models with direct model-ID routing.

**3. Tool and permission layer**  
[`packages/opencode/src/tool/registry.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/tool/registry.ts) builds the tool universe from built-ins, config-file tools, plugins, MCP, optional LSP, and optional code mode. [`packages/opencode/src/session/tools.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/session/tools.ts) converts those into AI SDK tools with per-call permission asks and metadata streaming.

**4. Provider and transport layer**  
[`packages/llm/README.md`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/llm/README.md) and the source in [`packages/llm/src`](https://github.com/anomalyco/opencode/tree/51f86c853791c41656fb0adcf9413291e4996b87/packages/llm/src) show the portable contract: one request language, one event stream, many provider adapters.

**5. Server and live-transport layer**  
[`packages/opencode/src/server/server.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/server/server.ts) starts the Effect-based HTTP server, prefers port `4096` when asked for `0`, tracks websockets, and optionally publishes mDNS. The OpenAI-specific transport note in [`packages/opencode/src/plugin/openai/README.md`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/plugin/openai/README.md) shows an additional optimization path: reuse per-session response sockets and fall back to HTTP after repeated failures.

### Request / data / control flow
1. A user action enters through [`packages/opencode/src/index.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/index.ts) or [`packages/cli/src/index.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/cli/src/index.ts).
2. [`prompt.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/session/prompt.ts) resolves session state, agent, model, prompt, references, and tools.
3. [`processor.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/session/processor.ts) pre-captures a snapshot, tracks text, reasoning, and tool parts, and settles tool calls into durable session records.
4. [`tool/registry.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/tool/registry.ts) and [`plugin/loader.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/plugin/loader.ts) load the callable surface.
5. [`server.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/server/server.ts) or the TUI/web layers project the live state to clients.

## Practical questions and answers
**Is this just a terminal skin over one vendor SDK?**  
No. The source separates CLI, server, provider protocols, tool registry, session state, plugins, and frontends into distinct packages.

**Where is the trust boundary around tool use?**  
Mostly in [`session/tools.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/session/tools.ts), [`tool/registry.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/tool/registry.ts), and the permission asks wired through the session processor.

**What is the sharpest implementation detail here?**  
Capturing the snapshot before streaming starts in [`processor.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/session/processor.ts). That is a real agent-runtime scar, not a demo trick.

**What looks brittle?**  
Prompt routing by model-ID substring in [`system.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/session/system.ts), a very large monorepo surface, and a few noisy or generic folders that make the core harder to discover.

## What is smart
- Splitting the provider-neutral LLM layer into [`packages/llm`](https://github.com/anomalyco/opencode/tree/51f86c853791c41656fb0adcf9413291e4996b87/packages/llm) instead of burying it in app code.
- Pre-snapshotting state before tool-executing streams begin in [`processor.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/session/processor.ts).
- Making the tool surface a registry with explicit plugin, MCP, permission, and truncation hooks in [`tool/registry.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/tool/registry.ts).
- Classifying plugin failure stages in [`plugin/loader.ts`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/plugin/loader.ts) instead of collapsing everything into "plugin failed."
- Reusing per-session OpenAI response sockets with clear fallback rules in [`packages/opencode/src/plugin/openai/README.md`](https://github.com/anomalyco/opencode/blob/51f86c853791c41656fb0adcf9413291e4996b87/packages/opencode/src/plugin/openai/README.md).

## What is flawed or weak
- The repo is big enough that the core runtime is easy to miss on first read.
- Some surface area feels messy or mixed-purpose, especially stray artifacts and generic package docs.
- Prompt specialization via model-name matching is practical but brittle.
- The system likely carries high maintenance cost because it spans providers, transport modes, plugins, MCP, TUI, web, desktop, and test matrices simultaneously.

## What we can learn / steal
- Separate provider normalization from agent orchestration early.
- Treat tool execution as first-class state, not as invisible side effects.
- Snapshot before the stream when tools may execute eagerly.
- Make plugin and MCP integration explicit subsystems with explainable failure modes.

## How we could apply it
If we were building our own coding agent, I would copy the architectural split almost directly: one small typed LLM core, one session/tool engine, and thin shells for CLI, API, and UI. I would keep the package count smaller, but the boundary placement here is strong.

## Bottom line
`OpenCode` is worth studying because the interesting work is not the marketing promise of "an open coding agent." The interesting work is the layered runtime underneath: provider-neutral streams, explicit tool state, session snapshots, plugin loading, and multiple shells over the same core.

The builder lesson is simple: treat agent runtime as infrastructure, not as prompt glue.
