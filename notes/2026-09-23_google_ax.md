## Executive summary

[google/ax](https://github.com/google/ax/tree/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601) is Google's open agentic orchestration runtime. The core idea is Kubernetes-shaped manifests for agent workloads: declare a [Task](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/pkg/apis/v1alpha1/ax.proto), bind it to a [Workspace](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/docs/concepts.md), constrain it with a [Gateway](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/examples/task.yaml), and let the controller create an isolated Agent Substrate actor.

The interesting part is the boundary drawing. AX does not try to become the agent framework. It owns lifecycle, state, workspace setup, egress policy, suspend/resume, and inspection. The agent process runs inside a task container through [runner/runner.go](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/runner/runner.go), while the control plane uses Redis streams and workers described in [DESIGN.md](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/DESIGN.md).

The project is early, but the shape is serious: typed protobuf APIs, a Go control plane, Redis-backed event queues, Kubernetes deploy manifests, and a task runner that sets up repos, skills, metadata, and guest services before the command starts.

## What they built

AX is a control plane for running many autonomous agent tasks in a cluster. Users write `ax.io/v1alpha1` YAML, then use the [cmd/ax](https://github.com/google/ax/tree/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/cmd/ax) CLI to apply, watch, suspend, resume, delete, and shell into tasks.

The product surface is four resource types defined in [pkg/apis/v1alpha1/ax.proto](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/pkg/apis/v1alpha1/ax.proto): `Task`, `Workspace`, `Gateway`, and `Model`. The runtime surface is a task container running [cmd/ax-task-runner/main.go](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/cmd/ax-task-runner/main.go), which loads the task and workspace specs from environment variables and hands them to the reusable [runner](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/runner/runner.go) package.

## Why it matters

Most agent systems put orchestration inside application code. AX moves a large part of that work into infrastructure. That matters because agent workloads are strange: they need isolation, mutable working directories, model credentials, tool access, suspend/resume, debug access, and network limits. Those are platform concerns.

The useful builder lesson is that agent infra looks less like "one more SDK" and more like a small scheduler with manifest contracts, status conditions, event queues, and sandbox probes.

## Layered architecture dissection

### High-level system shape

The system has a user plane, a control plane, and an execution plane. The user plane is [cmd/ax](https://github.com/google/ax/tree/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/cmd/ax), which behaves like a smaller `kubectl` for AX resources. The control plane is [ax-server](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/cmd/ax-server/main.go), [internal/server/server.go](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/internal/server/server.go), Redis, and [ax-controller](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/cmd/ax-controller/main.go). The execution plane is Agent Substrate plus the [ax-task-runner](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/cmd/ax-task-runner/main.go) inside each task container.

### Main layers

The API layer is explicit in [pkg/apis/v1alpha1/ax.proto](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/pkg/apis/v1alpha1/ax.proto). It exposes CRUD for tasks, gateways, workspaces, and models, plus task-specific `SuspendTask`, `ResumeTask`, and `WatchTask`.

The persistence layer is deliberately below Kubernetes CRDs. [DESIGN.md](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/DESIGN.md) says millions of short-lived tasks would push etcd past its comfort zone, so AX keeps state in Redis. [internal/store/redis/store.go](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/internal/store/redis/store.go) stores resources as protojson blobs, maintains sorted indexes, publishes task pubsub updates, and appends reconcile events to a Redis stream.

The reconciliation layer is [internal/controller/worker.go](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/internal/controller/worker.go) plus [internal/controller/reconciler.go](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/internal/controller/reconciler.go). Workers consume one event per group member, fetch the task, resolve gateway and workspaces, then reconcile against Agent Substrate.

The in-sandbox layer is [runner/runner.go](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/runner/runner.go). It starts metadata and guest services, sets up workspaces, launches the task command in its own process group, and keeps the sandbox inspectable after the command exits.

### Request / data / control flow

A user applies YAML like [examples/task.yaml](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/examples/task.yaml). The CLI parses manifests client-side and sends typed RPCs to the server. [internal/server/server.go](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/internal/server/server.go) validates and saves the resource.

Saving a task calls [internal/store/redis/store.go](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/internal/store/redis/store.go), which writes the task, indexes it, emits a `reconcile` event, and publishes the task to its watch channel. [internal/controller/worker.go](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/internal/controller/worker.go) consumes that event and invokes the reconciler.

The reconciler ensures the atespace, actor template, actor, and egress policy. It injects `AX_TASK_YAML`, `AX_WORKSPACES_YAML`, and optionally `GEMINI_API_KEY` into the actor template in [internal/controller/reconciler.go](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/internal/controller/reconciler.go). Once the actor is resumed, the controller polls `/readyz?check=workspace` until the in-container runner marks workspace setup complete.

Inside the container, [cmd/ax-task-runner/main.go](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/cmd/ax-task-runner/main.go) loads specs from environment or files. [runner/runner.go](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/runner/runner.go) calls [internal/workspace/setup.go](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/internal/workspace/setup.go), then starts the configured command.

## Important components

`TaskReconciler` in [internal/controller/reconciler.go](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/internal/controller/reconciler.go) is the most important component. It normalizes the task, injects environment, creates per-task actor templates, applies egress, resumes or suspends actors, and updates readiness conditions.

`Worker` in [internal/controller/worker.go](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/internal/controller/worker.go) is the scale-out loop. Multiple controllers can share a Redis stream group; each event is processed by one worker and acknowledged even if reconciliation failed, so a bad task does not wedge the queue.

`Run` in [runner/runner.go](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/runner/runner.go) is the agent's local init system. It starts metadata, configures environment, prepares mounted workspaces, starts the command, and handles process-group shutdown.

`SetupWorkspace` in [internal/workspace/setup.go](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/internal/workspace/setup.go) is where the declarative workspace becomes files on disk. The idempotent marker and retry-on-git-failure design are small but practical.

## Important knobs / configs / extension points

The manifest surface in [pkg/apis/v1alpha1/ax.proto](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/pkg/apis/v1alpha1/ax.proto) is the main extension point: task image, command, env, resources, workspace bindings, gateway reference, debug mode, Git repos, MCP servers, skills, listeners, allowlists, and model parameters.

The runner can be replaced or embedded. [docs/runner.md](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/docs/runner.md) and [runner/runner.go](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/runner/runner.go) make the task-container contract explicit.

Workspace bootstrap behavior is controlled through [internal/workspace/setup.go](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/internal/workspace/setup.go): Git depth, repo destination, skill path, `AX_BOOTSTRAP_TIMEOUT`, and the optional goal handed to the bootstrap script.

Network scope is declarative in the `Gateway` resource. [examples/task.yaml](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/examples/task.yaml) defaults to `*` on port 443, but the shape supports tighter egress host rules.

## Practical questions and answers

Q: Is AX an agent framework?
A: No. It is a workload runtime. The agent framework can be whatever command the task image runs. AX supplies manifests, isolation, workspace setup, network policy, lifecycle, and inspection.

Q: Why Redis instead of Kubernetes CRDs?
A: [DESIGN.md](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/DESIGN.md) argues that millions of short-lived tasks would overload etcd. Redis streams are used as the worker queue, and Redis keys/indexes store task state.

Q: What is the strongest implementation idea?
A: Treating task readiness as a composition of control-plane actor state and in-container workspace readiness. [internal/controller/reconciler.go](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/internal/controller/reconciler.go) waits on the runner's `/readyz?check=workspace`, so "Running" is not confused with "workspace is usable."

Q: Where would this fail first in production?
A: Secrets, egress defaults, and bootstrap reliability. The reconciler can fall back to controller environment credentials, [examples/task.yaml](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/examples/task.yaml) shows allow-all egress, and [internal/workspace/setup.go](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/internal/workspace/setup.go) intentionally treats bootstrap failures as non-fatal.

Q: What should we copy?
A: The resource split. `Task` for execution, `Workspace` for preparation, `Gateway` for network boundary, and `Model` for platform model config is a clean mental model.

## What is smart

AX keeps the public contract typed. [pkg/apis/v1alpha1/ax.proto](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/pkg/apis/v1alpha1/ax.proto) makes client/server behavior less hand-wavy than YAML-only systems.

It also respects scale pressure. The choice in [DESIGN.md](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/DESIGN.md) to keep task state out of etcd is a real systems decision, not just a style preference.

The runner boundary is also good. [runner/runner.go](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/runner/runner.go) gives custom images a library contract rather than forcing all users through one fixed binary.

## What is flawed or weak

The project is still pre-stable by its own [README.md](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/README.md). Expect resource fields, concepts, and CLI behavior to move.

The default egress posture shown in [examples/task.yaml](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/examples/task.yaml) is permissive. That is fine for a quick start, but dangerous if people cargo-cult it into real agent deployments.

Workspace bootstrap is intentionally forgiving. In [internal/workspace/setup.go](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/internal/workspace/setup.go), Git failures withhold the marker, but bootstrap failures only log and continue. That keeps tasks from hard-failing, but it can also start commands in an environment that is not actually ready.

## What we can learn / steal

Steal the idea that an agent task needs platform resources, not just prompt config. AX's [Task](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/pkg/apis/v1alpha1/ax.proto), [Workspace](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/docs/concepts.md), [Gateway](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/examples/task.yaml), and [Model](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/docs/concepts.md) split is reusable even outside this codebase.

Steal the readiness model. The control plane should know whether the sandbox process exists, whether network policy applied, and whether the workspace setup actually finished.

Steal the inspectability. `ax ssh`, guest services, metadata URLs, and post-command sandbox lifetime are exactly the kinds of features that make long-running agent systems debuggable.

## How we could apply it

For our own agent runs, we could define a smaller manifest schema with the same boundaries: workspace sources, network allowlist, model config, task command, and readiness probes. Even if we do not need a full cluster scheduler, that separation would make local and remote runs more reproducible.

For hosted agent workloads, AX is a reminder to keep event processing idempotent and observable. [internal/controller/worker.go](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/internal/controller/worker.go) and [internal/store/redis/store.go](https://github.com/google/ax/blob/d8ed0fe38bceb7842d3c47817d53d16ccdfcb601/internal/store/redis/store.go) are a useful pattern: persist desired state, publish reconcile events, and let workers converge the world.

## Bottom line

AX is early, but the architecture is worth studying because it takes agent workloads seriously as infrastructure. The best reusable lesson is not any one Go function. It is the product boundary: isolate the task, prepare the workspace, fence the network, persist state outside the cluster API server, and keep the sandbox inspectable.
