## Executive summary
[`alibaba/open-code-review`](https://github.com/alibaba/open-code-review/tree/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b) is an AI code-review CLI, GitHub Action, agent plugin package, and VS Code extension. The interesting part is the architecture claim in [`README.md`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/README.md): code review quality improves when brittle work is handled by deterministic code and the LLM is kept inside a task-specific loop with file tools, rule context, line positioning, and manifests.

The repo mostly backs that up. The CLI entry in [`cmd/opencodereview/review_cmd.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/cmd/opencodereview/review_cmd.go) freezes review inputs, validates resume identity, builds tool registries, initializes MCP clients, and runs an [`internal/agent`](https://github.com/alibaba/open-code-review/tree/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/agent) pipeline. The actual tool loop lives in [`internal/llmloop/loop.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/llmloop/loop.go), where each model round either calls tools, files comments, compresses context, or stops with a typed reason.

The strongest builder lesson is the split of responsibilities. File selection, grouping fallbacks, extension/path filters, token budgets, line relocation, comment schemas, retry reports, and coverage manifests are not left to prompt prose. The LLM is still central, but it runs inside guardrails described by source files like [`internal/agent/selection.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/agent/selection.go), [`internal/agent/grouping.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/agent/grouping.go), [`internal/tool/definitions.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/tool/definitions.go), [`internal/diff/relocation.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/diff/relocation.go), and [`internal/session/manifest.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/session/manifest.go).

## What they built
OpenCodeReview is a product-shaped code review system. It can run `ocr review` over workspace changes, branch ranges, or commits; `ocr scan` over whole files; `ocr delegate` for host-agent delegation; and it can publish results through a GitHub Action described in [`action.yml`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/action.yml). It is packaged as a Go CLI, npm wrapper, GitHub Action, website, plugin set, and editor extension.

The main runtime is Go. [`cmd/opencodereview/review_cmd.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/cmd/opencodereview/review_cmd.go) wires diff review; [`cmd/opencodereview/scan_cmd.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/cmd/opencodereview/scan_cmd.go) wires full-file scan; [`internal/agent/agent.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/agent/agent.go) owns diff-review orchestration; [`internal/scan/agent.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/scan/agent.go) owns scan orchestration; and [`internal/llm`](https://github.com/alibaba/open-code-review/tree/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/llm) adapts multiple LLM protocols.

The repo also ships a sizeable extension surface. [`plugins/open-code-review`](https://github.com/alibaba/open-code-review/tree/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/plugins/open-code-review) exposes agent integrations, [`skills`](https://github.com/alibaba/open-code-review/tree/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/skills) carries portable review skills, [`extensions/vscode`](https://github.com/alibaba/open-code-review/tree/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/extensions/vscode) mounts review comments into the editor, and [`pages`](https://github.com/alibaba/open-code-review/tree/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/pages) is the documentation/marketing site.

## Why it matters
Most AI code-review projects fail in boring ways: they miss files, hallucinate paths, drift line numbers, spam low-quality findings, or cannot explain what was covered. This repo's practical value is that it treats those as systems problems, not only prompt problems. [`internal/agent/selection.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/agent/selection.go) applies path, extension, deletion, and token gates before dispatch. [`internal/agent/grouping.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/agent/grouping.go) groups related files, but falls back deterministically if the grouping LLM fails. [`internal/session/manifest.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/session/manifest.go) defines a typed coverage contract so downstream users know whether the run was complete, partial, failed, or skipped.

It also matters because the repo is honest about review as workflow integration. [`action.yml`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/action.yml) has inputs for sticky summaries, incremental posting, severity/category routing, checkpoint ranges, budgets, timeouts, and provider selection. That is the unglamorous surface where review bots either become useful or become another notification tax.

## Layered architecture dissection
### High-level system shape
The system has four major layers. The bottom layer is git and file mechanics: parse diffs, resolve paths, read files at a frozen ref, and search through the repo. The second layer is deterministic review planning: filter unsupported files, match path-specific rules, group related changes, cap token usage, and seal resume identity. The third layer is the LLM loop: send task prompts, let the model use a small toolset, collect structured comments, compress context, and classify stop reasons. The top layer is delivery: CLI output, JSON manifests, GitHub PR comments, VS Code threads, plugin workflows, docs, and website.

That layering is visible in [`cmd/opencodereview/review_cmd.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/cmd/opencodereview/review_cmd.go). The command layer loads common context, validates git refs, resolves background context, validates resumes before creating sessions, constructs a file reader and tool registry, appends MCP tools, creates [`agent.New`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/agent/agent.go), runs it, freezes retry reports, emits output, and returns an exit status based on run-level error semantics.

### Main layers
**1. CLI and configuration layer**  
[`cmd/opencodereview/root.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/cmd/opencodereview/root.go), [`cmd/opencodereview/review_cmd.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/cmd/opencodereview/review_cmd.go), [`cmd/opencodereview/scan_cmd.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/cmd/opencodereview/scan_cmd.go), and [`cmd/opencodereview/provider_cmd.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/cmd/opencodereview/provider_cmd.go) turn user intent into typed options. The repo is careful about validation: review refs are checked before git use, resume identity is validated before session creation, and provider/model overrides are passed into the runtime as labels and hashes.

**2. Review input and selection layer**  
[`internal/agent/selection.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/agent/selection.go) is a good example of using boring code to protect AI behavior. It applies binary checks, user include/exclude rules, extension allowlists from [`internal/config/allowlist`](https://github.com/alibaba/open-code-review/tree/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/config/allowlist), default path excludes, deletion handling, and per-file diff token limits before the model sees a task.

**3. Rule and prompt layer**  
[`internal/config/rules/system_rules.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/config/rules/system_rules.go) loads ordered path rules with first-match behavior, brace expansion, and embedded language-specific docs. The repo's own [` .opencodereview/rule.json`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/.opencodereview/rule.json) shows the intended level of specificity: provider-registry changes must update multilingual docs and provider tests. Prompt budgets and tasks are configured by [`internal/config/template/task_template.json`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/config/template/task_template.json), whose knobs include grouping thresholds, max tool requests, max review rounds, and completion limits.

**4. Agent orchestration layer**  
[`internal/agent/agent.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/agent/agent.go) parses diffs, injects a diff map into tools, selects files, records skip reasons, estimates cost under a budget, records resume lineage, dispatches grouped subtasks concurrently, waits for background compression, finalizes the manifest, and returns comments. It delegates the inner conversation mechanics to [`internal/llmloop/loop.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/llmloop/loop.go).

**5. Tool loop layer**  
[`internal/llmloop/loop.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/llmloop/loop.go) is the engine room. `RunMainTask` repeatedly calls the configured model with tool definitions, executes tool calls, appends tool results, handles empty rounds, runs a final grace round when the tool-request budget is exhausted, and returns a `MainLoopStop` value such as `max_rounds`, `empty_rounds`, or `compression`. That stop classification is a serious maintainability win because coverage reports do not have to infer cause from strings.

**6. Built-in tool layer**  
[`internal/tool/definitions.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/tool/definitions.go) defines the narrow tool vocabulary: `task_done`, `code_comment`, `file_read`, `file_find`, `file_read_diff`, and `code_search`. [`internal/tool/file_read.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/tool/file_read.go) caps reads at 500 lines and reports truncation. [`internal/tool/code_search.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/tool/code_search.go) shells through `git grep`, has a timeout, caps matches, supports path patterns, and rejects path traversal.

**7. Comment positioning and session layer**  
[`internal/tool/code_comment.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/tool/code_comment.go) normalizes structured findings into categories and severities, while [`internal/diff/relocation.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/diff/relocation.go) gives the system a repair path when the submitted `existing_code` snippet does not locate cleanly. [`internal/session/manifest.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/session/manifest.go) turns that messy runtime into typed outcomes.

**8. Delivery layer**  
[`action.yml`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/action.yml) shows how much delivery logic exists around the CLI: provider setup, timeout bounds, upload artifacts, sticky summaries, incremental non-destructive posting, severity/category routing, checkpoint ranges, and review-comment batching. [`extensions/vscode/src/extension/providers/CommentProvider.ts`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/extensions/vscode/src/extension/providers/CommentProvider.ts) does the editor-side version by turning review comments into VS Code threads with suggestion application and stale-anchor handling.

### Request / data / control flow
A diff review starts in [`cmd/opencodereview/review_cmd.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/cmd/opencodereview/review_cmd.go). The command resolves output, loads repo/rules/templates, validates refs, resolves background context, validates a resume if present, builds the LLM runtime, creates a [`tool.FileReader`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/tool/filereader.go), registers tools, and calls [`agent.New`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/agent/agent.go).

Inside [`internal/agent/agent.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/agent/agent.go), `Run` loads and parses diffs, injects a read-only diff map, freezes tools, filters selected files, optionally estimates budget cost, groups files, and dispatches each group. For each group, the runner in [`internal/llmloop/loop.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/llmloop/loop.go) sends prompt messages and tool definitions to the provider client in [`internal/llm/client.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/llm/client.go). The model calls tools such as [`internal/tool/file_read.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/tool/file_read.go) or [`internal/tool/code_search.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/tool/code_search.go), submits findings through [`internal/tool/code_comment.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/tool/code_comment.go), then calls `task_done`.

After the model loop, comments are resolved against diffs and possibly re-located with [`internal/diff/relocation.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/diff/relocation.go). The run finalizes a session and a manifest using [`internal/session/manifest.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/session/manifest.go). Output then flows either to terminal/JSON, GitHub Action posting via [`action.yml`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/action.yml), or the VS Code UI in [`extensions/vscode`](https://github.com/alibaba/open-code-review/tree/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/extensions/vscode).

## Important components
`executeReviewContext` in [`cmd/opencodereview/review_cmd.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/cmd/opencodereview/review_cmd.go) is the best first read. It shows the whole product boundary: output writer, common context, ref validation, background context, resume loading, LLM runtime resolution, MCP integration, `agent.New`, quiet output handling, telemetry, retry report freezing, result emission, and error/manifest joining.

`Run` in [`internal/agent/agent.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/agent/agent.go) is the second read. It makes the deterministic/agent split concrete: parse diffs, inject tools, freeze tools, select files, record skipped cases, estimate budgets, dispatch subtasks, wait for background work, finalize coverage, and persist sessions.

`RunMainTask` in [`internal/llmloop/loop.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/llmloop/loop.go) is the core model-control primitive. It is not fancy, but it is disciplined: append task records before requests, attach request identity, aggregate usage, execute tool calls, retry empty tool rounds, compress context when needed, and classify why a task stopped.

[`internal/agent/grouping.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/agent/grouping.go) is a useful pattern because the LLM is used only when it buys something. One-file and small changesets bypass the grouping LLM; failed grouping falls back to one-file groups; oversized bundles are split by deterministic token budget checks.

[`internal/session/manifest.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/session/manifest.go) is the reliability component. It defines `ocr.run-manifest/v1`, input modes, failure classes, run failure classes, terminal states, and coverage items so the product can say exactly what happened.

## Practical questions and answers
**Is this mostly a prompt pack?**  
No. Prompt templates matter here, but the project value sits in code paths like [`internal/agent/selection.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/agent/selection.go), [`internal/agent/grouping.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/agent/grouping.go), [`internal/llmloop/loop.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/llmloop/loop.go), and [`internal/session/manifest.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/session/manifest.go). The repo is trying to make the prompt the flexible part, not the source of all invariants.

**What should a builder read first?**  
Start with [`cmd/opencodereview/review_cmd.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/cmd/opencodereview/review_cmd.go), then [`internal/agent/agent.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/agent/agent.go), then [`internal/llmloop/loop.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/llmloop/loop.go). After that, read [`internal/tool/code_comment.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/tool/code_comment.go) and [`internal/diff/relocation.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/diff/relocation.go) to understand why line anchoring is a first-class problem.

**What is the central architectural bet?**  
The bet is that code review should be decomposed before it is handed to an LLM. Deterministic selection, grouping, rules, line resolution, and manifests make the model's job narrower and make failures diagnosable. [`internal/agent/grouping.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/agent/grouping.go) captures that nicely: use an LLM for semantic grouping when it is worth the cost, but keep the fallback good enough to ship.

**Where would this fail in production?**  
Provider variability and operational complexity. [`internal/llm/client.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/llm/client.go) tries to preserve native turns across OpenAI/Anthropic-style providers, but review quality and tool-call behavior will still vary by model. The many knobs in [`action.yml`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/action.yml) are necessary, but they also create a large support surface.

**Is the VS Code extension incidental?**  
No. [`extensions/vscode/src/extension/providers/CommentProvider.ts`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/extensions/vscode/src/extension/providers/CommentProvider.ts) shows that comment anchoring and suggestion application are product problems, not just output formatting. It prepares review file status, resolves anchors against workspace/git snapshots, mounts threads when possible, and falls back to sidebar-only states when anchoring is unsafe.

## What is smart
- The repo treats coverage as a contract. [`internal/session/manifest.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/session/manifest.go) makes complete, partial, failed, and skipped states explicit.
- File selection is pure and shared by preview and real runs in [`internal/agent/selection.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/agent/selection.go). That avoids a classic "preview said one thing, execution did another" drift.
- [`internal/agent/grouping.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/agent/grouping.go) has pragmatic fallback behavior around LLM grouping instead of making the whole run depend on a clean JSON grouping response.
- [`internal/llmloop/loop.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/llmloop/loop.go) distinguishes model round budgets, empty rounds, compression stops, and errors. That kind of accounting is unglamorous but essential.
- The built-in tools in [`internal/tool/definitions.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/tool/definitions.go) are deliberately narrow. Builders should steal that instinct: a review agent does not need a general computer, it needs trustworthy source-reading and comment-filing primitives.
- [`action.yml`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/action.yml) reflects real CI scars: sticky summaries, incremental non-destructive posting, comment batching, severity routing, and checkpoint ranges are all practical affordances.

## What is flawed or weak
- The repo has a very large surface area for a young open-source project: CLI, npm packaging, plugin marketplace metadata, VS Code, GitHub Action, docs site, MCP, sessions, manifests, and multilingual docs. That breadth is impressive, but it makes regression coordination expensive.
- The public benchmark in [`README.md`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/README.md) is promising, but the causal claim is hard to audit from the repo alone. The architecture is plausible; the exact precision/F1 advantage still depends on dataset construction, judge calibration, and provider/model choice.
- The LLM loop is still a lot of state. [`internal/llmloop/loop.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/llmloop/loop.go) handles native turns, tool calls, empty retries, tool failures, compression, grace rounds, usage, and sessions in one place. It is readable, but a bug there is high blast radius.
- Provider compatibility is inherently brittle. [`internal/llm/client.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/llm/client.go) and [`internal/llm/providers.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/llm/providers.go) have to encode fast-moving model and protocol assumptions.
- The strongest product path requires careful setup. [`action.yml`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/action.yml) exposes many useful controls, but teams will need defaults, docs, and policy discipline to avoid noisy or underpowered reviews.

## What we can learn / steal
- Put deterministic code around the model. Use code for selection, grouping fallbacks, rule resolution, budgets, line resolution, and run manifests before asking an LLM to reason.
- Make preview and execution share the same pure selection function, as [`internal/agent/selection.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/agent/selection.go) does.
- Keep the tool vocabulary small. [`internal/tool/definitions.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/tool/definitions.go) is a compact lesson in domain-specific agent design.
- Treat comment anchoring as a workflow, not a line number. [`internal/diff/relocation.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/diff/relocation.go) and [`extensions/vscode/src/extension/providers/CommentProvider.ts`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/extensions/vscode/src/extension/providers/CommentProvider.ts) both reflect this.
- Emit durable run artifacts. [`internal/session/manifest.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/session/manifest.go) is a stronger product primitive than terminal logs.
- Design CI posting for repeat runs. [`action.yml`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/action.yml) makes sticky/incremental/checkpoint behavior explicit rather than relying on social convention.

## How we could apply it
For any internal AI reviewer, I would copy the same deterministic frame: build a stable diff parser, a file-selection function, a rule resolver, a bounded source-reading toolset, and a manifest before tuning prompts. The model should do judgment-heavy reading; the program should decide what was eligible, what was reviewed, what was skipped, and whether a finding can be anchored.

I would also copy the stop classification from [`internal/llmloop/loop.go`](https://github.com/alibaba/open-code-review/blob/6e5cd8cf2578768b6c6d1fafa1d14f66801d5f2b/internal/llmloop/loop.go). Any AI workflow that can run out of budget, compress itself into a corner, lose tool calls, or hit provider errors should persist that reason as a typed value, not bury it in prose.

The place I would be more conservative is product surface. If we were starting from scratch, I would ship the CLI plus JSON manifest first, then add GitHub posting and editor UI after the core coverage/comment-positioning contracts had proven stable.

## Bottom line
`alibaba/open-code-review` is worth studying because it turns AI review into a bounded system rather than a heroic prompt. Its best idea is not "LLMs can review code"; it is that code review agents need deterministic scaffolding around every fragile boundary: input identity, file selection, grouping, rules, tool access, line anchoring, budgets, retries, and delivery.

The repo is broad and still carries the complexity of a fast-moving product, but the builder lesson is strong: use the LLM for judgment, and use ordinary software engineering for the invariants that users will notice first when they break.
