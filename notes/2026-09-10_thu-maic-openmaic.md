I picked it because it is not only a demo classroom generator: it is a full Next.js app, a course-generation pipeline, a durable agent workbench, a published `@openmaic/*` package family, and a pluggable persistence/media/runtime stack.

## Executive summary
[`THU-MAIC/OpenMAIC`](https://github.com/THU-MAIC/OpenMAIC/tree/6afa5b0af64474146a34cf78d1b1bec3e7881bd8) is an open-source system for turning a topic or source material into an interactive AI classroom. The surface story is "one prompt in, a whole course out"; the source story is more interesting. A Next.js 16 app exposes classroom routes, editor/workbench views, media generation endpoints, persistence endpoints, and a durable agent runtime. The generation path is split across the app's server modules and the reusable [`packages/@openmaic/generation`](https://github.com/THU-MAIC/OpenMAIC/tree/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/packages/%40openmaic/generation) package, while documents, assets, runtime sessions, and user skills live behind the [`packages/@openmaic/storage`](https://github.com/THU-MAIC/OpenMAIC/tree/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/packages/%40openmaic/storage) abstraction.

The best engineering lesson is that OpenMAIC treats course generation as a staged production pipeline rather than one giant prompt. [`lib/server/classroom-generation.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/classroom-generation.ts) resolves model routes per stage, optionally rewrites web-search queries, generates outlines, creates agent profiles, generates scene content and actions, then runs media, TTS, and persistence as separate phases. The agent workbench path is also serious: [`lib/server/agent-runtime/runner.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/agent-runtime/runner.ts) claims durable sessions with leases, builds a pi-agent runtime, registers only capability-backed tools, and writes an event stream that can survive client disconnects.

The weak point is the same thing that makes the repo fascinating: scope. It is a classroom builder, slide editor, multimodal generation harness, skill runtime, storage backend, media exporter, import/export system, and agent workbench in one codebase. That means the real product quality depends less on any single model call and more on whether all the seams stay boring.

## What they built
They built a full-stack AI classroom product. The top-level [`README.md`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/README.md) describes slides, quizzes, interactive simulations, project-based learning, whiteboard/TTS, `.pptx` export, local ASR/TTS providers, and OpenClaw/Codex-compatible skills. [`package.json`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/package.json) shows the actual implementation center: a pnpm monorepo with Next.js, React 19, LangGraph, pi-agent packages, AI provider SDKs, document parsing, PPTX generation, ProseMirror editing, Playwright tests, and internal workspace packages.

The classic one-click generation path starts at [`app/api/generate-classroom/route.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/app/api/generate-classroom/route.ts). That route validates a `requirement`, creates a job, returns a polling URL, and schedules [`runClassroomGenerationJob`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/classroom-job-runner.ts) with Next's `after()` hook. The heavy work then runs in [`generateClassroom`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/classroom-generation.ts), not in the route.

The newer workbench path lives under [`app/api/agent`](https://github.com/THU-MAIC/OpenMAIC/tree/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/app/api/agent) and [`lib/server/agent-runtime`](https://github.com/THU-MAIC/OpenMAIC/tree/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/agent-runtime). It lets a background agent plan, create, revise, import, search, generate media, and patch course documents through tools. The bundled skill package at [`skills/openmaic/SKILL.md`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/skills/openmaic/SKILL.md) makes the product callable from agent workbenches, while the many generation skills under [`skills/agent-runtime`](https://github.com/THU-MAIC/OpenMAIC/tree/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/skills/agent-runtime) encode reusable course-building styles and constraints.

## Why it matters
OpenMAIC matters because it is a concrete example of an agentic content product escaping the "single prompt, single output" shape. A course is a tree of durable artifacts: outline, stage metadata, scenes, actions, media references, narration, materials, edit history, and export bundles. OpenMAIC models that explicitly.

It also shows what provider-neutral AI software looks like when the project is serious about optionality. The environment surface in [`.env.example`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/.env.example) supports OpenAI, Azure OpenAI, Anthropic, Bedrock, Gemini, DeepSeek, Qwen, Kimi, MiniMax, Grok, OpenRouter, Doubao, Tencent, Xiaomi, Ollama, Lemonade, FunASR, multiple TTS providers, ASR providers, media extraction, and PDF processing. That breadth is operationally messy, but it is the right mess for a self-hostable education tool.

The repo is especially useful to study because it has product-level compromises in the source. [`docker-compose.yml`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/docker-compose.yml) separates the app, optional Postgres persistence, and an isolated video render service. The render service is opt-in because Chromium and FFmpeg are heavy, and the compose file describes an internal render network plus egress lockdown. That is the kind of unglamorous boundary a real multimedia app needs.

## Layered architecture dissection
### High-level system shape
OpenMAIC has two product modes on the same substrate. The one-click mode is a server-driven generation pipeline: request in, background job out, poll until a persisted course is ready. The workbench mode is a durable background agent session: conversation in, tools mutate stage documents, event streams keep the UI current, and persisted sessions can be resumed or cancelled.

Both modes converge on the same course document idea. Scenes are generated, edited, rendered, narrated, exported, and stored as structured stage data rather than as a final blob.

### Main layers
**1. HTTP and app shell layer**  
[`app/api/generate-classroom/route.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/app/api/generate-classroom/route.ts) is deliberately thin: parse JSON, validate `requirement`, create a job, schedule background work, and return a 202 response with polling metadata. The larger route set under [`app/api`](https://github.com/THU-MAIC/OpenMAIC/tree/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/app/api) exposes the same product capabilities in smaller pieces for the interactive UI.

**2. Classroom generation layer**  
[`lib/server/classroom-generation.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/classroom-generation.ts) owns the one-click pipeline. It resolves a model for `generate-classroom`, validates required provider keys, optionally does web search, generates scene outlines through [`generateSceneOutlinesFromRequirements`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/packages/%40openmaic/generation/src/outline-generator.ts), creates agents, then iterates scenes with [`generateSceneContent`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/packages/%40openmaic/generation/src/scene-generator.ts) and [`generateSceneActions`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/packages/%40openmaic/generation/src/scene-generator.ts).

**3. Model and provider routing layer**  
The pipeline does not blindly use one model for everything. [`lib/server/classroom-generation.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/classroom-generation.ts) caches stage-specific routes such as `scene-content`, `scene-content:<type>`, `scene-actions`, `agent-profiles`, and `web-search-query-rewrite`. The knobs are backed by [`lib/server/model-routes.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/model-routes.ts), [`lib/server/resolve-model.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/resolve-model.ts), and provider config in [`.env.example`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/.env.example).

**4. Agent runtime layer**  
[`lib/server/agent-runtime/runner.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/agent-runtime/runner.ts) is the durable session engine. It imports session leases and stores from [`@openmaic/storage`](https://github.com/THU-MAIC/OpenMAIC/tree/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/packages/%40openmaic/storage), builds agents with [`lib/agent/runtime/build-agent.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/agent/runtime/build-agent.ts), and assembles tools through [`lib/server/agent-runtime/runner-contract.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/agent-runtime/runner-contract.ts). The important boundary is that tools are capability-gated and owner-scoped.

**5. Course document tool layer**  
[`lib/server/agent-runtime/course-tools.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/agent-runtime/course-tools.ts) builds the workbench's document toolset: DSL reads/patches, generation tools, PPT import, image/video generation, deck editing, TTS, and material media insertion. It wraps stage-id tools with `withOwnerStageAuthorization` and marks document writers sequential using [`lib/agent-runtime/stage-writer-tools.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/agent-runtime/stage-writer-tools.ts), which is a good example of translating agent-risk into a scheduler constraint.

**6. Storage and deployment layer**  
[`packages/@openmaic/storage/src/index.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/packages/%40openmaic/storage/src/index.ts) exports browser, HTTP, and Postgres-backed KV/document/asset/runtime stores, plus agent session and user-skill stores. [`docker-compose.yml`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/docker-compose.yml) turns that into a deployable topology with optional Postgres and optional isolated render service.

### Request / data / control flow
In one-click mode, the request enters [`app/api/generate-classroom/route.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/app/api/generate-classroom/route.ts). A job record is created by [`lib/server/classroom-job-store.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/classroom-job-store.ts). [`lib/server/classroom-job-runner.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/classroom-job-runner.ts) marks it running, calls [`generateClassroom`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/classroom-generation.ts), and persists success or failure. The generation pipeline moves through researching, outline generation, scene content, scene actions, media, TTS, and persistence.

In workbench mode, the user posts messages to the agent session API under [`app/api/agent`](https://github.com/THU-MAIC/OpenMAIC/tree/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/app/api/agent). The runner in [`lib/server/agent-runtime/runner.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/agent-runtime/runner.ts) claims a session, builds a pi `Agent` via [`buildAgent`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/agent/runtime/build-agent.ts), and lets tools mutate course documents. Each successful document writer emits a durable checkpoint through [`lib/server/agent-runtime/course-tools.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/agent-runtime/course-tools.ts), so the UI can follow real persisted state rather than trusting partial model text.

## Important components
The one-click job route in [`app/api/generate-classroom/route.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/app/api/generate-classroom/route.ts) is small in the right way. It creates a durable-ish job and gets out of the request path. The matching [`lib/server/classroom-job-runner.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/classroom-job-runner.ts) keeps an in-memory `runningJobs` map, marks progress, and records failure without letting duplicate invocations pile onto the same job id.

[`lib/server/classroom-generation.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/classroom-generation.ts) is the spine of the old path. The detail worth stealing is stage-specific model routing: outline generation, scene content, scene actions, agent profiles, and search rewrite can each resolve a different model, but bad optional routes degrade back to the classroom model rather than aborting the whole run.

The agent runner in [`lib/server/agent-runtime/runner.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/agent-runtime/runner.ts) is the spine of the new path. It treats background execution as a lease-coordinated process with event logs, interruption, resume, element references, session materials, and owner-scoped document access. That is much more realistic than binding an agent's lifetime to one browser tab.

[`lib/server/agent-runtime/course-tools.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/agent-runtime/course-tools.ts) is where agent power gets made safe enough to use. It registers generation, import, media, deck, and DSL tools, but wraps stage-targeted tools with ownership checks and marks document-writing tools sequential. The shared [`STAGE_WRITER_TOOL_NAMES`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/agent-runtime/stage-writer-tools.ts) list prevents the server scheduler and client write-ownership logic from drifting apart.

The storage package in [`packages/@openmaic/storage/src/index.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/packages/%40openmaic/storage/src/index.ts) matters because it makes OpenMAIC more than a local demo. Browser stores, HTTP stores, Postgres stores, asset stores, runtime stores, agent-session stores, and user-skill stores share one public package boundary.

- Scene generation behavior is exposed through [`packages/@openmaic/generation`](https://github.com/THU-MAIC/OpenMAIC/tree/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/packages/%40openmaic/generation), including outlines, scene content, scene actions, retries, PBL planning, and prompt formatting.
- Agent tool availability is assembled in [`lib/server/agent-runtime/runner-contract.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/agent-runtime/runner-contract.ts) and [`lib/server/agent-runtime/course-tools.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/agent-runtime/course-tools.ts).
- The skill layer is just files, which is the right extension shape for agent behavior. See [`skills/agent-runtime`](https://github.com/THU-MAIC/OpenMAIC/tree/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/skills/agent-runtime) and [`skills/openmaic/references`](https://github.com/THU-MAIC/OpenMAIC/tree/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/skills/openmaic/references).
- Deployment behavior changes by Docker Compose profile in [`docker-compose.yml`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/docker-compose.yml): default app, optional `server-persistence`, and optional `video-export`.

## Practical questions and answers
**Is this mostly a fancy README around prompts?**  
No. The source has real application machinery. [`lib/server/classroom-generation.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/classroom-generation.ts), [`lib/server/agent-runtime/runner.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/agent-runtime/runner.ts), [`packages/@openmaic/storage`](https://github.com/THU-MAIC/OpenMAIC/tree/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/packages/%40openmaic/storage), and [`docker-compose.yml`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/docker-compose.yml) are product infrastructure, not marketing filler.

**Where would I look first if generation quality is bad?**  
Start with [`packages/@openmaic/generation/src/outline-generator.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/packages/%40openmaic/generation/src/outline-generator.ts), [`packages/@openmaic/generation/src/scene-generator.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/packages/%40openmaic/generation/src/scene-generator.ts), and the stage routing logic in [`lib/server/classroom-generation.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/classroom-generation.ts). Bad quality might be prompt design, but it might also be the wrong model assigned to `scene-content:<type>`.

**What is the most production-minded part?**  
The workbench's document write discipline. [`lib/server/agent-runtime/course-tools.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/agent-runtime/course-tools.ts) explains why writers are sequential: parallel read-modify-write tools can silently erase each other's changes. That comment is evidence of a team debugging real agent behavior.

**What is the riskiest part to self-host?**  
The optional media/export stack. LLM-only generation is one category of risk; Chromium, FFmpeg, file extraction, external media providers, and untrusted HTML capture are another. The isolation comments in [`docker-compose.yml`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/docker-compose.yml) are worth reading before turning on MP4 export.

## What is smart
- The app splits route handling from background work in [`app/api/generate-classroom/route.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/app/api/generate-classroom/route.ts) and [`lib/server/classroom-job-runner.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/classroom-job-runner.ts).
- [`lib/server/classroom-generation.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/classroom-generation.ts) treats web search, media generation, and TTS as optional phases that can fail without destroying the whole classroom.
- Stage-specific model routing lets operators spend strong models on hard scene types and cheaper models on query rewrite or routine actions.
- [`lib/server/agent-runtime/course-tools.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/agent-runtime/course-tools.ts) makes owner authorization and sequential document writes central rather than scattered.
- [`packages/@openmaic/storage`](https://github.com/THU-MAIC/OpenMAIC/tree/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/packages/%40openmaic/storage) creates a clean seam between app logic and persistence backend.
- The external [`skills/openmaic`](https://github.com/THU-MAIC/OpenMAIC/tree/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/skills/openmaic) package is a nice distribution idea: make the product accessible from other workbenches without forcing every integration through the web UI.

## What is flawed or weak
- The surface area is huge. A bug in model routing, document migration, agent leases, media placeholders, asset storage, or render isolation can look to a user like "the course generator is bad."
- Provider neutrality in [`.env.example`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/.env.example) is powerful, but every provider knob increases the support matrix.
- The one-click path uses in-memory state while generating scenes before persistence through [`createInMemoryStore`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/classroom-generation.ts). That keeps the path simple, but very long generations still depend on the server process staying alive until the persist phase.
- The workbench runtime in [`lib/server/agent-runtime/runner.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/agent-runtime/runner.ts) is necessarily complex. Leases, resumes, event compaction, element references, material extraction, and tool-call repair are all correct problems to solve, but each needs tests and operational observability.

## What we can learn / steal
- Treat generated courses as structured documents early. The [`@openmaic/dsl`](https://github.com/THU-MAIC/OpenMAIC/tree/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/packages/%40openmaic/dsl) and [`@openmaic/storage`](https://github.com/THU-MAIC/OpenMAIC/tree/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/packages/%40openmaic/storage) split is worth copying for any AI content app.
- Use small, named generation phases. OpenMAIC's outline, content, actions, media, TTS, and persistence phases are easier to debug than one giant call.
- Make tool writers sequential by declaration, as in [`lib/server/agent-runtime/course-tools.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/agent-runtime/course-tools.ts), when tools mutate the same document.
- Keep external skills as files. [`skills/openmaic/SKILL.md`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/skills/openmaic/SKILL.md) shows a portable integration channel that is cheaper than a bespoke SDK for every agent host.
- If exporting untrusted HTML/video, isolate the renderer by default. The [`render-service`](https://github.com/THU-MAIC/OpenMAIC/tree/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/render-service) plus [`docker-compose.yml`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/docker-compose.yml) pattern is worth remembering.

## How we could apply it
For our own builder workflows, I would copy the staged pipeline and the document-writer discipline first. A smaller version could generate an outline, create one structured artifact per section, attach source/media references, then persist after each section instead of waiting until the whole product is done. The key lesson from [`lib/server/agent-runtime/course-tools.ts`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/agent-runtime/course-tools.ts) is that agent tools need concurrency rules as much as they need schemas.

I would also adopt OpenMAIC's capability-gated tool registration. Let the model see `generate_video` only when video generation is configured, just as [`buildDslCourseToolset`](https://github.com/THU-MAIC/OpenMAIC/blob/6afa5b0af64474146a34cf78d1b1bec3e7881bd8/lib/server/agent-runtime/course-tools.ts) only includes video tools when the provider is available. Tool absence is a better UX than giving the model a button that can only fail.

## Bottom line
OpenMAIC is worth studying because it is a real agentic product stack, not just an impressive classroom demo. The core builder insight is that generated educational media is a document system: outlines, pages, actions, assets, narration, tools, sessions, and exports need durable boundaries.

The repo's best ideas are staged generation, provider-neutral routing, capability-gated agent tools, sequential document writers, pluggable storage, and isolated rendering. Its main risk is breadth. This much product in one codebase can be powerful, but only if the boring seams stay well tested.
